# SDP — Software Development Platform

## Что это

SDP — это AI PDLC + SDLC: платформа, которая ведёт идею от первого описания до задеплоенной фичи с доказательствами на каждом шаге. Не инструмент для запуска агентов — а полноценная AI-команда разработки, где исследование, планирование, реализация и выход в прод организованы как единый управляемый процесс.

Главная идея проста: AI-агенты пишут код, но без структуры это просто vibes. SDP превращает работу агентов в процесс, который можно проверить, повторить и масштабировать.

## Обещание

Пользователь описывает идею. Discovery-агенты исследуют, задают вопросы, формируют спецификацию и принимают решение о scope — всё это с записанными рассуждениями. Затем Delivery-агенты реализуют фичу через структурированные фазы: планирование, сборка, ревью, оценка. На выходе — PR с доказательствами того, что именно было сделано и почему. Без «агент сказал, агент сделал» — с реальным следом.

## Две фазы

**Discovery** — исследовательская фаза. Запускается командой `sdp discover`, проводит council из нескольких моделей, выдаёт спецификацию и решение по scope. Входные данные — идея в произвольной форме. Выход — структурированный spec, готовый к реализации. Discovery не предполагает, а исследует.

**Delivery** — фаза реализации. `agentloop` — конечный автомат (discover → plan → build → review → eval), который ведёт задачу от spec до PR. Каждый переход между состояниями — gate с проверкой. Агент не может перейти к следующему шагу, не оставив доказательств предыдущего.

## Для кого

**Greenfield.** Новый проект, нет процессов — SDP задаёт их с первого дня. Идея сразу попадает в управляемый цикл.

**Brownfield.** Существующий репозиторий, есть кодовая база. SDP подключается локально, не требует переписывать инфраструктуру.

**Legacy и сложные системы.** Там, где агент без контекста ломает больше, чем чинит — Discovery фаза строит карту перед тем как Delivery фаза трогает код.

**Команды и операторы.** Когда несколько разработчиков или несколько проектов нужно вести параллельно — Operator Mode даёт board-to-delivery управление с единой точкой контроля.

## Два режима

**Local Mode** — SDP внутри одного репозитория. Беads опционален. Минимальный setup, агентный цикл работает локально. Подходит для одного разработчика или небольшой команды, которая хочет структуру без overhead'а.

**Operator Mode** — полный путь от board до деплоя. Beads обязателен как операционная истина. Несколько проектов, параллельные workstreams, gates с human-in-the-loop. Для команд, которым нужна управляемость на уровне организации.

## Что SDP не является

SDP — не CI/CD. CI/CD запускает пайплайны после того, как код написан. SDP управляет процессом до того.

SDP — не governance layer поверх существующих агентов. Это сама AI-команда — со своей Discovery фазой, своим циклом Delivery, своей моделью доказательств.

SDP — не agentloop wrapper. agentloop — один из компонентов Delivery фазы, не вся система.

SDP — не замена разработчику. Это инструмент, который делает работу AI-агентов прозрачной, проверяемой и воспроизводимой — чтобы разработчик мог доверять тому, что агент сделал.
