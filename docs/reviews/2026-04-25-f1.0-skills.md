# Release-1.0 Readiness Review: Skill Surface

## Inventory summary
- Scope checked: `prompts/skills/*.md` (targeted as requested).
- `prompts/skills` contains 28 skill directories with `SKILL.md`.
- `prompts/commands` contains 24 command markdown files.
- `prompts/commands.yml` contains 30 command mappings.
- Declared requirement in request (“41 skill files”) does not match repository reality.
- `.agents/skills` is a separate legacy surface (43 files) and is not aligned with `prompts/skills` naming.

## Consistency findings
- Frontmatter inconsistency is pervasive in `prompts/skills`:
  - 28/28 files have YAML frontmatter with `name` and `description`.
  - 14/28 files omit `version`.
  - 28/28 files omit `compatibility`.
- Uniform section shape is not implemented:
  - All 28 skills are missing required `purpose`, `triggers`, `steps`, `outputs`, `anti-patterns` sections.
- `prompts/commands` frontmatter drift:
  - 24/24 have frontmatter present, but 23/24 omit `name`.
  - 23/24 omit `version` and `compatibility`.
  - `prompts/commands/deliver.md` has no frontmatter.
- Command docs use `agent:` values that point to names not represented in canonical agent registries (builder/fixer/analyst/debugger).
- Frontmatter and naming in `prompts/commands.yml` and markdown command files are not harmonized (legacy path conventions mixed).

## Workflow correctness findings
- Several skills reference commands they then rely on that are not present in current `cmd/sdp/main.go` command set: `drift`, `guard`, `health`, `init`, `quality`.
- `build`/`protocol-consistency`/`review` skills claim `sdp` entrypoints that do not exist in the published root CLI.
- `review` skill claims all 7 reviewers always spawn (`qa`, `security`, `devops`, `sre`, `techlead`, `docs`, `promptops`) but canonical `prompts/agents` only contains 13 agents with no `docs` or `promptops`, and role mismatch (`techlead` vs `tech-lead`).
- `.agents/skills`/commands.yml currently defines/uses legacy aliases extensively (`legacy alias for ...`) but command runtime references are not always wired to the same surface.
- `.claude/commands/deliver.md` documents `@delivery-loop` though the referenced entrypoint is not present in the requested prompt skill surface.
- Several command docs imply behavior from binary-specific orchestration that is not documented in `prompts/commands/*.md` in a stable way.

## Gap analysis
- `prompts/commands.yml` has 11 mapped command keys with no corresponding `prompts/commands/*.md` file:
  - `fix`, `understand`, `operate`, `landscape`, `scout`, `architect`, `metrics`, `plan`, `git-worktree`, `parallel-dispatch`, `llm-council`, `strataudit`.
- `prompts/commands/*.md` has 7 files not represented in `prompts/commands.yml`:
  - `beads`, `codereview`, `deliver`, `prd`, `protocol-consistency`, `submit-to-swarm`, `test`.
- Command mappings in `prompts/commands.yml` reference CLI subcommands that are not present in `cmd/sdp/main.go`: `apply`, `quality`, `landscape`, `prd`, `drift`, `verify`, `ci-triage` references vary by context.
- Skills in `prompts/skills` reference `sdp` commands that are not defined by the CLI registry, creating dead execution paths.
- There are additional command binaries in `cmd/` that are not represented in CLI command docs or command mapping, suggesting a partial public surface (`sdp-a2a`, `sdp-beads-bridge`, `sdp-ci-loop`, `sdp-control`, `sdp-doc-sync`, `sdp-evidence`, `sdp-gh-findings-sync`, `sdp-harness`, `sdp-healthcheck`, `sdp-omc-guard`, `sdp-orchestrate-daemon`, `sdp-protocol-check`, `sdp-ready`, `sdp-session-audit`, `sdp-up`, `sdp-ws-verdict-validate`).
- `prompts/commands.yml` still routes `file:` fields to `.agents/skills` and also to legacy non-existent aliases in places, not to `prompts/skills` uniformly.

## Stale content
- Significant name drift between old and new skill namespaces:
  - Commands and command metadata mention legacy names (`feature-delivery`, `delivery-loop`, `fix`, `understand`, `operate`, `research`, `session-audit`, etc.) not reflected in `prompts/skills`.
- `prompts/commands.yml` `agents:` section lists `builder`, `developer`, `tester`, and `analyst`, but canonical prompt agents surface does not include these as canonical command-target agents.
- `commands.yml` references `quality-reviewer`, `documentation`, `product-manager`, `analyst` in several `llm_subagents` lists; these names are not in canonical command-facing agent definitions.
- `@vision`/`prd` linkage and command references are legacy-oriented and not consistently normalized to current `sdp` command names.
- The `.claude/commands` surface remains hybrid (symlink for commands plus raw markdown), and some command names only exist in one surface.

## Trigger quality
- Most skills do not explicitly codify negative/skip conditions; descriptions are usually “what to do” without disambiguating “when not to run.”
- `design`, `discovery`, `feature`, `idea`, `vision`, and `reality*` overlap conceptually without explicit precedence or exclusivity.
- `issue`, `bugfix`, `hotfix`, `fix` lineage is semantically ambiguous and largely alias-based; callers can easily invoke wrong-risk paths.
- `tdd`, `think`, and `go-modern` have limited or implicit gating language and no explicit user-facing trigger boundaries.
- Several skills describe behavior as legacy aliases but do not define migration-safe transition conditions.

## Recommended next actions
- Lock the authoritative skill set: decide whether release-1.0 targets 28 `prompts/skills` or 43 `.agents/skills`, and remove contradictory 41-skill assumption from review scope.
- Enforce a single schema requirement for all prompt surface files: frontmatter keys (`name`, `description`, `version`, `compatibility`) and structural sections (`purpose`, `triggers`, `steps`, `outputs`, `anti-patterns`).
- Align `prompts/commands.yml` to the same surface by removing undocumented command keys and adding missing docs for intended keys.
- Replace unresolved CLI targets in skills and mappings with valid `cmd/sdp/main.go` commands.
- Normalize `llm_subagents` and `agents:` references to existing canonical agents.
- Add explicit negative triggers and precedence docs for overlapping skills (`issue`/`bugfix`/`hotfix`/`fix` family and `design`/`vision`/`reality` family).
- Add a preflight consistency checker that validates skill→command→agent→binary references on every change.
