## 2) Contract conformance

- **PreToolUse JSON contract**: `jq` parsing of stdin JSON is implemented in `.claude/hooks/PreToolUse.sh:13-14` and `.claude/hooks/PostToolUseWorkflowCheck.sh:11-13`. Contract semantics (block on exit !=0) are used correctly for tool filtering.
- **Stop gate JSON contract**: `stop_hook_active` is parsed in `scripts/oneshot-stop-gate.sh:16-18`; JSON payload contract is present but payload read path is conditional on FIFO stdin.
- **Exit code conventions** are generally observed for blockers (2) vs allow (0).
- **Major conformance gap**: `.opencode` and `.cursor` hooks do not receive equivalent PreToolUse/PostToolUse semantics as Claude; they only provide partial/one-way coverage (OpenCode pre-tool only, Cursor stop only).

## 3) Idempotency audit

- `scripts/bd_post_close.sh` is mostly idempotent: moves are guarded by source/destination checks and frontmatter updates are applied only when moving.
- `scripts/hooks/post-bd-close-sync.sh` is also mostly idempotent with done/backlog checks.
- `scripts/install_bd_hooks.sh` is idempotent in expected paths (marker + alias reuse) when same shell RC exists.
- `scripts/install-bd-post-close-hook.sh` claims idempotency in help text and removes/re-adds marker safely.
- `scripts/install-hooks.sh` is **not idempotent-by-contract** because it can abort before completion on non-file entries in `scripts/hooks` (directory copy failure), leaving half-installed state.

## 4) Exit code audit

- **Blockers intentionally enforced (2)**:
  - `.claude/hooks/PreToolUse.sh:20-39,60-69` returns 2 on destructive/constraint violations.
  - `scripts/hooks/validators/*.sh` return 2 on hard CA rules.
  - `scripts/oneshot-stop-gate.sh:35-36` returns 2 when CI is incomplete.
- **Allow (0) paths**:
  - Non-tool inputs in PreToolUse/PostToolUse hooks and successful bd-close wrappers typically return 0.
- **Potential silent bypass**:
  - Several scripts invoke external dependencies without strict fail-stop semantics in non-critical branches, which can produce skip behavior (`set +` not used, but `|| true` and guarded checks). This is intentional in places but hides failure mode in guard chains.

## 5) Failure modes

- `scripts/install-hooks.sh` is the highest-risk failure point: `cp` without `-r` over a directory causes immediate install abort on first directory copy (`scripts/hooks/validators`), so install is broken on a clean repo.
- `scripts/oneshot-stop-gate.sh` relies on `jq` and will fail hard with malformed/absent checkpoint JSON unless guarded.
- `oneshot-stop-gate` payload path checks only FIFO stdin (`-p /dev/stdin`), so in non-FIFO harness variants stop gate metadata can be ignored.
- `sdp-omc-guard` dependency in OpenCode config is unguarded; missing binary leads to hook error/exit failure, not a controlled allow path.
- BD post-close wrappers require user shell state alignment and do not enforce detection of already-installed competing wrappers, so order/race can silently switch behavior.

## 6) Determinism + speed

- No explicit sleeps are present in the reviewed hook scripts.
- `PreToolUse` may call `sdp-guard`; if `sdp-guard` executes external checks, PreToolUse latency can become variable and non-deterministic.
- `scripts/oneshot-stop-gate.sh` is deterministic O(n) over checkpoints/runs files.
- Install scripts are fast but brittle because they fail on traversal/filename assumptions.

## 7) Cross-harness coverage parity

- Parity is partial at best:
  - Claude: PreToolUse + PostToolUseWorkflow + Stop.
  - OpenCode: PreToolUse only.
  - Cursor: Stop only.
  - Codex: no hook config present in `.codex`.
- `sdp/hooks` and `scripts/hooks` are divergent copies, not strict mirrors (diff both in behavior and available files).

## 8) Install scripts audit

- `scripts/install-hooks.sh` currently copies *everything* from `scripts/hooks` into `.git/hooks` and `chmod +x` target, including non-hook helpers and directories.
- `scripts/hooks/install-git-hooks.sh` and `sdp/hooks/install-git-hooks.sh` only install `pre-commit` and `pre-push`, which is behaviorally inconsistent with `scripts/install-hooks.sh`.
- `scripts/install_bd_hooks.sh` and `scripts/install-bd-post-close-hook.sh` provide overlapping strategies for bd post-close interception; operationally they can conflict.
- `sdp/hooks/install-hooks.sh` is mostly a deprecated placeholder and does not align with current local hook inventory.

## 9) Settings drift

- `.claude/settings.json` is wired to specific scripts and currently references the intended Hook scripts by command string.
- There is drift: `PostToolUse.sh` exists in `.claude/hooks` but is **not** wired (`PostToolUseWorkflowCheck.sh` is the active file).
- `.cursor/hooks.json` has stop hook coverage but no PreToolUse equivalent.
- `.opencode/hooks/pre-tool-use.json` has different command and scope semantics than Claude.

## 10) Environment safety

- No clear secrets are printed in hook outputs.
- Multiple scripts assume invocation from repo root or a cwd where relative paths resolve (`bash .claude/hooks/...`, `bash scripts/oneshot-stop-gate.sh`, `scripts/bd_post_close.sh` path assumptions).
- Wrapper installers write to shell rc files and rely on shell type heuristics; mis-detection can lead to partial install behavior.

## 11) Test coverage

- Existing automated coverage: `scripts/oneshot-stop-gate_test.sh` and `scripts/bd_post_close_test.bats`.
- Missing coverage:
  - No tests for install scripts (`scripts/install-hooks.sh`, `scripts/hooks/install-git-hooks.sh`, `sdp/hooks/install-git-hooks.sh`, `scripts/install_bd_hooks.sh`, `scripts/install-bd-post-close-hook.sh`).
  - No tests for stop-hook behavior under OpenCode/Cursor variants.
  - No tests for `sdp/hooks` vs `scripts/hooks` drift.
  - No harness-level execution tests for `.claude/settings.json` hook wiring.
