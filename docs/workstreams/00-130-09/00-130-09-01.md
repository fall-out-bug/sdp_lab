# 00-130-09-01: DRAFT prefix in bootstrap generation

Feature: F130 (AI Harness Config Auto-Provisioning)

## Goal

Modify bootstrap artifact generation to emit files with `DRAFT-` prefix. CLAUDE.md and AGENTS.md are written as DRAFT- prefixed copies requiring explicit human curation before committing. Policies, hooks, and beads are NOT DRAFT-prefixed.

## Beads

- sdplab-4xs

## Scope Files

- `internal/bootstrap/bootstrap.go` — modify `Execute()` to write DRAFT- prefixed files
- `internal/bootstrap/types.go` — add `DraftPrefix` field to `BootstrapConfig`, `UseDraft` bool
- `internal/bootstrap/claude_md.go` — add DRAFT header to generated CLAUDE.md content
- `internal/bootstrap/agents_md.go` — add DRAFT header to generated AGENTS.md content
- `internal/bootstrap/bootstrap_test.go` — test DRAFT file naming and header content

## Acceptance Criteria

- [ ] `BootstrapConfig.UseDraft` defaults to `true` — all generated files get `DRAFT-` prefix
- [ ] Generated files: `DRAFT-CLAUDE.md`, `DRAFT-AGENTS.md` (policies, hooks, and beads are NOT DRAFT-prefixed)
- [ ] Each file starts with: `<!-- DRAFT: generated by sdp bootstrap YYYY-MM-DD. Review, curate, then rename (remove DRAFT- prefix) before committing. -->`
- [ ] TODO markers: `<!-- TODO: verify this rule matches intended behavior -->` appended to every generated rule section
- [ ] Existing tests continue passing (backward compat for non-DRAFT path when `UseDraft=false`)
- [ ] Unit tests for DRAFT header injection and TODO marker insertion

## Out of Scope

- Pre-commit hook (WS-02)
- Doctor check (WS-03)
- CI flags (WS-04)
- Documentation (WS-05)

## Implementation Notes

Follow the existing template pattern: embedded templates via `//go:embed`, `text/template` rendering, idempotent file writes. The DRAFT header is injected as a prefix to the rendered template output, NOT embedded in templates themselves (keeps templates clean, header logic centralized).
