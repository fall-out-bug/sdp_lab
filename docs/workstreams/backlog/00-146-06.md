# 00-146-06: Bench harness `sdp-decompose-bench` and A/B report

Feature: F146 (Inference Decomposition Framework)

Design reference: [2026-04-26-f146-inference-decomposition-design.md §3 F146-06](../../plans/2026-04-26-f146-inference-decomposition-design.md)

## Goal

Ship the A/B benchmarking command and the evidence report. For each fixture in the (reused F144) ws-verdict corpus, run both monolithic and decomposed paths, capture latency / tokens / cost / accuracy, generate a markdown comparison report with a verdict on the decomposition hypothesis. Extract the corpus-loading helpers shared with `sdp-confidence-replay` into `internal/inference/replayutil/` (refactor without semantic change to confidence-replay).

## Beads

- sdplab-23zc (historical leaf issue)

## Scope Files

- `internal/inference/replayutil/loader.go` — new. Corpus walker, fixture parser; reused by both bench cmds.
- `internal/inference/replayutil/evidence.go` — new. Evidence writer (per-run JSON, aggregate CSV).
- `internal/inference/replayutil/loader_test.go` — new.
- `cmd/sdp-confidence-replay/main.go` — modify. Refactor to use `replayutil/`; behavior 1:1 unchanged (regression test fixture).
- `cmd/sdp-decompose-bench/main.go` — new. Entry point: `sdp-decompose-bench --corpus <path> --out <report.md>`.
- `cmd/sdp-decompose-bench/runner.go` — new. Per-fixture runner: invokes monolithic + decomposed, collects metrics.
- `cmd/sdp-decompose-bench/report.go` — new. Markdown renderer with per-fixture rows + aggregate sections.
- `docs/research/2026-04-26-f146-decomposition-replay-report.md` — new (artifact). First report run output committed.

## Acceptance Criteria

- [ ] `internal/inference/replayutil/` exposes `LoadCorpus(path) ([]Fixture, error)` and `WriteEvidence(dir, runID, payload)` — used by both replay cmds.
- [ ] `cmd/sdp-confidence-replay` refactored to use `replayutil/` with no behavioral change — its existing tests still pass (regression test).
- [ ] `cmd/sdp-decompose-bench --corpus <path>` walks fixtures, runs both monolithic and decomposed for each, writes evidence under `internal/build/.sdp/evidence/<run-id>/`.
- [ ] Per-fixture row in CSV: `id | category | monolithic_status | decomposed_status | latency_mono | latency_decomp | tokens_mono | tokens_decomp | cost_mono | cost_decomp`.
- [ ] Aggregate sections in markdown report:
  - latency p50 / p95 (mono vs decomp)
  - total tokens (mono vs decomp, % delta)
  - accuracy (% match against `golden_status` from fixture, mono vs decomp)
  - TOON token saving (% vs JSON marshal of aggregate output) — reads bench fixture from 00-146-02 stitcher bench.
  - cost USD (mono vs decomp, % delta).
- [ ] Hypothesis verdict block at top of report — evidence-backed statement on token saving / latency overhead / accuracy delta.
- [ ] Bench runs locally and under `go test -tags=replay ./cmd/sdp-decompose-bench/...` (not blocking main CI).
- [ ] Acceptance thresholds (informational, not blocking merge):
  - decomposed accuracy ≥ monolithic accuracy (no regression).
  - decomposed total tokens ≤ monolithic × 0.85 (≥ 15 % saving).
  - decomposed latency p50 ≤ monolithic × 1.30 (≤ 30 % overhead).
  - decomposed cost ≤ monolithic × 0.70 (≥ 30 % saving via Haiku on extract/aggregate).
  - TOON tokens ≤ JSON tokens × 0.60 (≥ 40 % saving on aggregate output).
- [ ] First report committed at `docs/research/2026-04-26-f146-decomposition-replay-report.md` with actual numbers (not placeholders).
- [ ] `go build ./...` and `go vet ./...` clean.

## Out of Scope

- New corpus design — explicitly reuses F144 ws-verdict corpus (acknowledged bias in design §4 Risks).
- Continuous re-run / nightly scheduling — manual invocation in v1.
- Multi-corpus aggregation — single corpus per run.
- Auto-update of report on prompt/pricing changes — manual re-run, doc note in README.
