# 00-131-01: Skill template library — stack-specific marker convention

Feature: F131 (sdplab-ait)

## Goal

Audit the existing 43 skills in `.agents/skills/` and determine which benefit from stack-specific sections. Create a `<!-- STACK_SPECIFIC:BEGIN -->` / `<!-- STACK_SPECIFIC:END -->` marker convention so that downstream tooling (F131-02 augmenter) can inject language/stack-specific blocks without clobbering hand-written content.

## Beads

- sdplab-g8t (F131-01)

## Scope Files

- `.agents/skills/*.md` — audit target (read-only for this WS)
- `docs/reference/skill-marker-convention.md` — new. Documents marker syntax, supported stacks, and which skills use markers.
- `.agents/skills/build.md` — candidate for first marker injection (POC).

## Acceptance Criteria

- [ ] Audit table: every skill in `.agents/skills/` classified as "needs-stack-specific" or "stack-agnostic"
- [ ] Marker convention documented: `<!-- STACK_SPECIFIC:BEGIN section="test" -->` / `<!-- STACK_SPECIFIC:END -->`
- [ ] At least 4 skills identified that need stack-specific sections (expected: build, test, debug, ci-triage)
- [ ] POC: `build.md` updated with marker blocks for Go, Python, TypeScript test commands
- [ ] Idempotency: re-running marker injection produces identical output

## Out of Scope

- Augmenter tool (→ 00-131-02)
- Bootstrap integration (→ 00-131-03)
- Creating per-language skill variants (the opposite approach — rejected in audit)
