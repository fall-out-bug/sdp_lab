# 00-146-01: Core decomposition library — Pipeline, Stage, Result types

Feature: F146 (Inference Decomposition Framework)

Design reference: [2026-04-26-f146-inference-decomposition-design.md §3 F146-01](../../plans/2026-04-26-f146-inference-decomposition-design.md)

## Goal

Ship the generic `decompose` library kernel: `Pipeline[Final]`, `Stage[In, Out]`, `Result[Final]`, `StageResult`, `StageTrace`, `AggregateTrace`, `StageConfig`, `FailurePolicy`. Pipeline composition through fluent `.Then()` with type-erased internal storage and runtime type-check. Foundation for all subsequent F146 workstreams.

## Scope Files

- `internal/inference/decompose/pipeline.go` — new. `Pipeline[Final]`, `New[Final](name)`, `Then(stage, cfg)`, `Run(ctx, in)`.

## Acceptance Criteria

- [ ] `Pipeline[Final]` constructed via `decompose.New[Final](name)`; `Then(stage, cfg)` adds a stage with type-check at construction time.
- [ ] `Pipeline.Run(ctx, in)` executes stages sequentially, propagates context cancellation, populates `Result.StageResults` per stage.
- [ ] `Stage[In, Out]` interface — `Run(ctx, in In) (Out, StageTrace, error)`, `Name()`. Constructor `NewStage[In, Out](name, fn)` accepts a func.
- [ ] `FailurePolicy.Abort` — first stage error returns from Pipeline.Run with that error wrapped.
- [ ] `FailurePolicy.RetryOnce` — stage retried once with same input on first error; second failure follows Abort path.
- [ ] `FailurePolicy.Fallback` — stage error swapped for `StageConfig.FallbackOut` (typed any), pipeline continues.
- [ ] `StageConfig.Timeout` enforces per-stage deadline via context.WithTimeout; expiry returns `context.DeadlineExceeded` from stage.
- [ ] `Result.Score` computed as mean of `StageResult.SubScore` (per-stage SubScore set later by Confidence wrap; default `1.0` if stage OK without Confidence, `0.0` if FAIL).
- [ ] `Result.Status` aggregation: any stage FAIL → Result FAIL (unless Fallback used); any stage UNSURE without FAIL → Result UNSURE; all OK → OK.
- [ ] Generic type-mismatch (e.g. `s1: Stage[A, B]` chained with `s2: Stage[C, D]` where `C != B`) detected at construction (compile-time or in `NewStage`/`Then` validation panic).
- [ ] Unit tests cover (a) happy 3-stage path, (b) stage 2 fail → Abort, (c) stage 2 fail → RetryOnce → recover, (d) stage 2 fail → Fallback, (e) per-stage timeout, (f) generic mismatch caught.
- [ ] Coverage `go test -cover ./internal/inference/decompose/...` ≥ 85 %.
- [ ] README documents canonical 3-stage construction example end-to-end.
- [ ] `go build ./...` and `go vet ./...` clean.

## Out of Scope

- Stitcher implementations (→ 00-146-02).
- Confidence/cascade wrapping per stage (→ 00-146-03).
- Any LLM call from Stage.Run (covered later via adapters; tests use mock fns).
- Branching DAG / parallel stages — sequential only in v1 (Open question §7-3).
- YAML/JSON pipeline configuration (Non-goal).
