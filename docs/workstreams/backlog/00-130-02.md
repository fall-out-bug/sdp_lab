# 00-130-02: Pattern Extraction Engine — Extend Scout for Convention Mining

Feature: F130 (sdplab-9nb)

## Goal

Extend `internal/scout` to extract structured code conventions from the scanned project. Add a `Conventions` section to `ProjectCard` that captures naming patterns, module structure, test layout, lint config, and CI workflow conventions.

## Beads

- sdplab-lld

## Scope Files

- `internal/scout/types.go` — add `Conventions` struct to `ProjectCard`
- `internal/scout/conventions.go` — new: convention extraction logic
- `internal/scout/conventions_test.go` — new: tests

## Acceptance Criteria

- [ ] `Conventions` struct added to `ProjectCard` with fields: `ModulePatterns []ModulePattern`, `TestStructure TestLayout`, `LintConfig *LintInfo`, `CIWorkflow *CIInfo`
- [ ] `conventions.go` extracts conventions from files already walked by scout (no extra I/O)
- [ ] `pattern-report.json` emitted by scout contains populated `Conventions` section for Go projects
- [ ] Unit tests: convention extraction on fixture Go project matches expected patterns
- [ ] Backward-compatible: `Conventions` zero-value is valid (nil slices/pointers)

## Out of Scope

- Rules file generation (F130-03)
- Harness adapter rendering (F130-04)
- Multi-language support beyond Go (future)

## Implementation Notes

- Reuse `WalkContext` from existing scout walk
- `ModulePattern`: {Name, Pattern, Examples []string} — e.g. "repository", "pkg/repo/*.go"
- `TestLayout`: {Style string, DirPattern string} — e.g. "colocated" or "testdir"
- `LintInfo`: {Tool string, ConfigFile string, Rules []string}
- `CIInfo`: {System string, ConfigFile string, Steps []string}
- Do NOT create a new analysis engine — extend the existing visitor pattern in scout
