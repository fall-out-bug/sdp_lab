# 00-105-11: LLM Integration + Architecture Hypothesis

Feature: F105 (AI Architect)

## Goal

Implement the LLM integration layer for Phase 2 interpretation: prompt templates for ArchitectureHypothesizer, PatternDetector, and RiskAssessor, with token budget management, output parsing, and cost tracking.

## Beads

- (will be created when workstream is claimed)

## Scope Files

- `internal/architect/llm/client.go` — LLM client abstraction (local + cloud providers)
- `internal/architect/llm/client_test.go`
- `internal/architect/llm/prompt_hypothesizer.go` — ArchitectureHypothesizer prompt templates
- `internal/architect/llm/prompt_patterns.go` — PatternDetector prompt templates
- `internal/architect/llm/prompt_risks.go` — RiskAssessor prompt templates
- `internal/architect/llm/parser.go` — structured output parsing from LLM responses
- `internal/architect/llm/parser_test.go`
- `internal/architect/llm/budget.go` — token budget management per tier
- `internal/architect/llm/cost.go` — cost tracking and reporting

## Acceptance Criteria

- [ ] LLM client abstraction supports: local models (Ollama/LM Studio), OpenAI, Anthropic — pluggable provider interface
- [ ] ArchitectureHypothesizer prompt generates scored style hypotheses across 8 ArchStyle types with confidence intervals
- [ ] PatternDetector prompt identifies architectural patterns with evidence citations from CodebaseProfile
- [ ] RiskAssessor prompt identifies architectural risks and debt indicators
- [ ] Token budget management enforces: Tier 1 (~2K), Tier 2 (~5-15K per container), Tier 3 (~10-30K per component)
- [ ] All LLM inputs pass through SecurityFilter before sending
- [ ] LLM outputs parsed into structured Go types (StyleHypothesis, PatternFinding, RiskFinding)
- [ ] Cost tracking records: input tokens, output tokens, model used, estimated cost per call
- [ ] All LLM calls logged to audit log via SecurityFilter (sanitized input hash, timestamp, token count)

## Out of Scope

- Fine-tuning or training custom models
- Streaming LLM responses (batch only for MVP)
- RAG-based context retrieval for very large codebases (deferred to Phase D)
- Multi-model consensus (council-of-models) at runtime

## Implementation Notes

- From section 1.1: Phase 2 is LLM Interpretation on sanitized profile only — never raw code
- From section 1.2: context assembly is question-driven — design review uses Tier 1 + selective Tier 2
- From section 1.3: output is "hypothesis" not "detection" — always includes confidence intervals and evidence
- Low-confidence hypotheses explicitly marked "requires human validation"
- HumanInputNeeded field lists styles that cannot be determined from code alone
- SecurityFilter must be applied to all profile data before any LLM call (depends on 00-105-01)
- Prompt templates should request structured JSON output for reliable parsing
- Cost tracking helps teams understand LLM expenditure per analysis run
- Local LLM is default path — cloud providers require explicit opt-in via AllowExternalLLM flag
- From design decisions: "Hybrid: structural extraction -> CodebaseProfile -> LLM interpretation" (7/7 models consensus)
