# 00-168-02: Onboarding truth audit and promise map

Feature: F168 (sdplab-o8gk)
Design reference: [F168 design](../../plans/2026-05-13-f168-onboarding-quality-taxonomy-design.md)

## Goal

Audit the current onboarding path against actual CLI and installer behavior, then
produce a promise map that makes shipped, beta, experimental, stale, and missing
surfaces explicit.

- `docs/reference/product-surface.md`

## Acceptance Criteria

- [ ] `sdp orchestrate` docs distinguish `sdp orchestrate once|loop` from standalone `sdp-orchestrate --feature`.
- [ ] `bootstrap` help/docs list the same currently supported flags.
- [ ] Quickstart, project map, product surface, and CLI reference use one stable first-run surface list.
- [ ] Existing `index` follow-up commands are either documented as second-run value or intentionally left out with rationale.
- [ ] `architect` is classified consistently as buyer-visible second-run value or operator-only tooling.

- Rewriting historical archive docs.
- Publishing to the public `sdp` repo.
- Building new CLI features solely because old docs mentioned them.
