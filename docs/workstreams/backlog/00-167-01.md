# 00-167-01: F167 Security Verdict Contract

Feature: F167 (sdplab-xe5c)
Phase: Pilot Evidence & Spec Quality
Status: Backlog

## Goal

Define the machine-readable security verdict contract for the Day-14 runtime
gate. The contract must make Critical/High blocking, Medium/Low advisory, and
provider/evidence failure explicitly non-passing.

## Acceptance Criteria

- [ ] Verdict schema captures gate status, severity, file/line location, finding rationale, suggested fix, reviewer metadata, and evidence references.
- [ ] Severity mapping is explicit: Critical/P0 and High/P1 block; Medium/P2 and Low/P3 warn but allow.
- [ ] Provider failure, malformed verdict, missing test evidence, or missing sanitizer evidence produces `escalated`, not `pass`.
- [ ] Prompt contract is Go/SDP-oriented and checks hardcoded secrets, PII in logs, HTTP endpoints, shell/path injection, input validation, unsafe auth persistence, and trust-boundary violations.
- [ ] Prompt contract focuses on exploitable security defects and policy boundary risks; broad maintainability/style review remains out of scope for this gate.
- [ ] Test-double contract defines fixed reviewer verdict fixtures for pass, warn, block, malformed output, and provider failure.
- [ ] Contract tests validate clean, warn-only, block, and escalated verdict fixtures.
- [ ] Targeted tests pass without live provider credentials.

## Out of Scope

- Running live model calls.
- Implementing gateway sanitation.
- Agentloop integration.
- Replacing F164 prompt-injection corpus or review policy.
