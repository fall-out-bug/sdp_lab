# 00-164-02: Static corpus schema and validation

Feature: F164 (sdplab-9wxx)

## Goal

Define the machine-readable prompt-injection corpus contract, minimum provenance fields, PromptOps schema extension decision, and deterministic static validation.

## Beads

- sdplab-9wxx.2

## Scope Files

- `schema/prompt-injection-corpus.schema.json`
- `schema/promptops-check.schema.json`
- `internal/evals/pi_corpus.go`
- `internal/evals/pi_corpus_test.go`
- `cmd/sdp-eval/main.go`
- `cmd/sdp-eval/main_test.go`
- `docs/security/f164-prompt-injection-test-cases.md`
- `docs/security/f164-prompt-injection-threat-model.md`

## Dependencies

- 00-164-01

## Acceptance Criteria

- [ ] A corpus schema captures case id, class, surface, trust source, allowed/forbidden tools, expected behavior, forbidden behavior, authoritative layer, and evidence expectation.
- [ ] Minimum provenance fields are defined for tool result, human approval, policy decision, and model judgment.
- [ ] PromptOps schema extension decision is explicit: extend existing schema, create dedicated PI schema, or both.
- [ ] Static validation rejects malformed cases and missing trust/tool/evidence fields.
- [ ] Static validation enforces at least one benign control case and at least one supply-chain case.
- [ ] A fixture proves keyword-block-only classification fails validation when benign controls are absent or mislabeled.
- [ ] `go test ./internal/evals ./cmd/sdp-eval` passes.

## Out of Scope

- Live-provider evals.
- Runtime write-tool enforcement.
- Mock-model behavioral assertions; those belong to 00-164-03.
