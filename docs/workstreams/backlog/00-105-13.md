# 00-105-13: Evaluation Harness + Golden Test Repos

Feature: F105 (AI Architect)

## Goal

Build the evaluation harness framework and golden test repositories that other workstreams use for validation. This starts in week 2 alongside extractors -- NOT at the end -- so every extractor can validate against golden repos as it is built.

## Beads

- (will be created when workstream is claimed)

## Scope Files

- `internal/architect/eval/harness.go` -- evaluation harness framework
- `internal/architect/eval/harness_test.go`
- `internal/architect/eval/golden.go` -- golden repo test suite management
- `internal/architect/eval/golden_test.go`
- `internal/architect/eval/metrics.go` -- precision/recall/F1 measurement per ecosystem
- `internal/architect/eval/metrics_test.go`
- `internal/architect/eval/mock.go` -- mock extractor outputs for unit testing
- `internal/architect/eval/mock_test.go`
- `internal/architect/eval/fixtures/` -- golden test case directories per language

## Acceptance Criteria

- [ ] Evaluation harness framework: load golden repo, run analysis, compare against expected results
- [ ] Metrics computed per ecosystem: precision, recall, F1 for import accuracy, style hypothesis, and C4 generation
- [ ] Mock extractor outputs for unit testing pipeline stages without running real extractors
- [ ] Golden test cases for Go: simple CLI, multi-module monorepo, gRPC service, Gin REST API
- [ ] Golden test cases for Python: Flask app, FastAPI project, Django monolith
- [ ] Golden test cases for Java/Kotlin: Spring Boot monolith, Gradle multi-project
- [ ] Golden test cases for TypeScript/JS: Next.js app, NestJS service, Express API, monorepo with workspaces
- [ ] Golden test cases for SQL: migration directory, ORM models (GORM, SQLAlchemy, Prisma), schema.sql
- [ ] Golden test cases for cross-repo: microservices repo with docker-compose, monorepo with mixed languages
- [ ] Exit criteria targets encoded as testable assertions: Go >90% import/>85% style, Python/Java >65% import/>75% style, TS/JS >65% import/>70% style, SQL >80% schema
- [ ] Evaluation runs are CI-friendly: deterministic, no LLM calls, <60s for full suite

## Out of Scope

- LLM-based evaluation (evaluating LLM output quality -- deferred to Phase B)
- Fuzz testing of extractors
- Performance benchmarking (separate concern)
- CI/CD integration wiring (WS12 responsibility)

## Implementation Notes

- This workstream starts in week 2 alongside the language extractors (05-08) so each extractor can validate incrementally
- Golden repos are minimal fixture directories checked into the repository, not external dependencies
- Each golden repo has an `expected.json` file describing the correct extraction results
- Mock extractors allow pipeline stages (assembly, C4 generation, LLM interpretation) to be tested independently
- Metrics collection is the same framework used by WS12 CLI integration for exit criteria validation
- From council review: evaluation must not be an afterthought -- it is a P0 workstream that runs parallel to extraction
- Precision >95% requirement (low false positives) before any CI gate integration
- False positive budget: <5% -- a single false block erodes all trust
