# 00-166-06: local chunked LLM guard classifier

Feature: F166 (sdplab-mp83)

## Goal

Add a local LLM classifier layer to the F166 gateway design so SDP can make
context-aware allow/redact/block decisions without trusting a remote provider
with risky prompts. The classifier must handle small local context windows by
chunking large prompts, classifying each chunk, reducing verdicts, and preserving
global byte spans for deterministic redaction.

## Acceptance Criteria

- [ ] Design states deterministic scanner remains the first security layer and
  local LLM classification is not the sole security boundary.
- [ ] Design supports any local OpenAI-compatible endpoint, with Ollama and LM
  Studio treated as presets.
- [ ] Classifier contract returns structured JSON with action, risk level,
  categories, reason, confidence, and chunk-local suggested spans.
- [ ] Oversized prompt handling defines chunk metadata, stable byte offsets,
  overlap, structural splitting order, and reducer semantics.
- [ ] Reducer rules define block/redact/needs_review aggregation, span merging,
  timeout/error behavior, and strict vs demo policy.
- [ ] Audit requirements include classifier model/endpoint class, chunk count,
  failed chunk ids, classifier completeness, final reducer verdict, and no raw
  secrets.
- [ ] Test plan requires fake local endpoint calls, multi-chunk prompts, boundary
  overlap, global span preservation, reducer escalation, timeout/error paths, and
  malformed classifier JSON.
- [ ] Socratic review evidence records critic/judge outcome and author
  resolutions before implementation planning.

## Out of Scope

- Using local LLM output as the byte-level redactor.
- Live local-model tests in CI.
- Streaming classifier support.
- Replacing deterministic `llmguard.Scanner`.
