# 00-166-06: local chunked LLM guard classifier spec

Feature: F166 (sdplab-mp83)

## Goal

Specify the local LLM classifier layer for the F166 gateway design so SDP can
make context-aware allow/redact/block decisions without trusting a remote
provider with risky prompts. The classifier must handle small local context
windows by chunking large prompts, classifying each chunk, reducing verdicts, and
preserving global byte spans for deterministic redaction.

## Acceptance Criteria

- [x] Design states deterministic scanner remains the first security layer and
  local LLM classification is not the sole security boundary.
- [x] Design supports any local OpenAI-compatible endpoint, with Ollama and LM
  Studio treated as presets.
- [x] Classifier contract returns structured JSON with action, risk level,
  categories, reason, confidence, and chunk-local suggested spans.
- [x] Oversized prompt handling defines chunk metadata, stable byte offsets,
  overlap, structural splitting order, and reducer semantics.
- [x] Reducer rules define block/redact/needs_review aggregation, span merging,
  timeout/error behavior, and strict vs demo policy.
- [x] Audit requirements include classifier model/endpoint class, chunk count,
  failed chunk ids, classifier completeness, final reducer verdict, and no raw
  secrets.
- [x] Test plan requires fake local endpoint calls, multi-chunk prompts, boundary
  overlap, global span preservation, reducer escalation, timeout/error paths, and
  malformed classifier JSON.
- [x] Socratic review evidence records critic/judge outcome and author
  resolutions before implementation planning.
