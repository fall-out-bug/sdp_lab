# 00-166-02: llmguard scanner and redactor core

Feature: F166 (sdplab-mp83)

## Goal

Implement the reusable `internal/llmguard` core: findings, scan traces, scanner,
redactor, policy, verdict states, and deterministic scanner/redactor tests. This
workstream has no provider calls and no HTTP server.

## Beads

- sdplab-dutb

## Scope Files

- `internal/llmguard/` (new package)
- `docs/plans/2026-05-03-f166-runtime-llm-guard-gateway-design.md`

## Acceptance Criteria

- [x] `Scanner` returns findings and scan traces for raw, base64-decoded, and split-joined scan paths.
- [x] Detection rules cover OpenAI-style `sk-` / `sk-proj-`, GitHub `ghp_`, AWS `AKIA`, bearer tokens, emails, Luhn-valid card-like numbers, phones, base64 secrets, and simple split secrets.
- [x] Simple split secrets are limited to same-message, ordered fragments with at most 16 ASCII non-alphanumeric separator bytes (`[^A-Za-z0-9]`).
- [x] Scanner enforces max input bytes, max decoded candidate bytes, and one base64 decode pass, returning budget status for `scan_budget_exceeded`.
- [x] `Redactor` supports typed operator/audit placeholders and untyped provider placeholders.
- [x] `Policy` and verdict state constants include all states defined by the design.
- [x] Tests include at least 10 deterministic cases plus known-miss tests for accepted regex limitations.
- [x] Tests assert scanner/redactor outputs never include raw corpus secrets where redaction is expected.
- [x] Test fixtures use synthetic non-routable credentials and standard test card numbers only.

## Out of Scope

- Wrapping `modelgateway.Provider`.
- Writing JSONL audit events.
- Cost estimation.
- HTTP proxy or rate limiting.
- Streaming support.
