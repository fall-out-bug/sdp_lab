# 00-105-03: Language-Agnostic Extractors

Feature: F105 (AI Architect)

## Goal

Implement the four language-agnostic extractors that analyze any repository regardless of ecosystem: FileTreeExtractor, DependencyManifestParser, SpecInventoryScanner, and GeneratedCodeDetector.

## Beads

- (will be created when workstream is claimed)

## Scope Files

- `internal/architect/extract/filetree.go` — directory structure, naming patterns, directory conventions
- `internal/architect/extract/filetree_test.go`
- `internal/architect/extract/manifest.go` — multi-ecosystem dependency manifest parsing
- `internal/architect/extract/manifest_test.go`
- `internal/architect/extract/spec_inventory.go` — OpenAPI, AsyncAPI, Proto, GraphQL, ADR scanning
- `internal/architect/extract/spec_inventory_test.go`
- `internal/architect/extract/generated.go` — generated code detection and tagging
- `internal/architect/extract/generated_test.go`
- `internal/architect/extract/extractor.go` — Extractor interface definition

## Acceptance Criteria

- [ ] Extractor interface defined with `Extract(ctx, path) -> ExtractorOutput` contract
- [ ] FileTreeExtractor detects naming patterns (snake_case, camelCase dirs) and directory conventions (src/, lib/, cmd/, pkg/, internal/)
- [ ] DependencyManifestParser handles: go.mod, package.json, Cargo.toml, pom.xml, build.gradle, requirements.txt, pyproject.toml, Gemfile, *.csproj
- [ ] SpecInventoryScanner locates: OpenAPI (*.yaml with openapi: field), AsyncAPI, .proto files, GraphQL schemas (.graphql), ADR documents (ADR-*.md or in docs/adr/)
- [ ] GeneratedCodeDetector matches all patterns: `// Code generated by`, `// DO NOT EDIT`, `@Generated`, `# Generated by`, `/* eslint-disable */`, `__generated__/`, `*.pb.go`, `*.pb.ts`
- [ ] Generated files tagged `generated: true` in profile and excluded from import graph / conformance analysis
- [ ] Detect at least 3 of 5 cross-language patterns: API spec sharing (OpenAPI/Proto references across services), Protobuf/gRPC service definitions with client usage, DB schema/ORM correlation (migration files matched to ORM models), message contract sharing (shared event schemas), shared type libraries (published packages used by multiple services)
- [ ] All extractors return structured data compatible with CodebaseProfile assembly

## Out of Scope

- Language-specific import graph extraction (workstreams 05-08)
- SQL analysis (workstream 09)
- Infrastructure extraction (workstream 04)

## Implementation Notes

- From section 1.1: These are Phase 1 deterministic extractors — pure Go, no LLM
- FileTreeAnalyzer provides: directory structure, naming patterns
- DependencyManifestParser: go.mod, package.json, Cargo.toml, pom.xml, etc.
- SpecInventoryScanner: OpenAPI, AsyncAPI, Proto, GraphQL, ADR, Docker, Terraform, CI
- GeneratedCodeDetector: exclude from analysis to avoid false dependencies (section 1.6)
- From section 1.5: Cross-language dependency detection patterns (API client/server, Protobuf/gRPC, database schema, message contracts, shared types)
- Each extractor should be independently testable with fixture directories
- **Parallelization note**: FileTreeExtractor, DependencyManifestParser, SpecInventoryScanner, GeneratedCodeDetector can be parallelized within this workstream — they share no internal state and write to independent sections of the ExtractorOutput
