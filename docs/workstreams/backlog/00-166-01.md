# 00-166-01: Runtime LLM Guard Gateway design contract

Feature: F166 (sdplab-mp83)

## Goal

Lock the core-first design for a reusable Go runtime guard around SDP LLM calls.
The feature keeps the spirit of the day-13 LLM Gateway challenge, but applies it
to SDP's model-call boundary rather than building a generic provider proxy.

## Acceptance Criteria

- [x] Design states why SDP should not clone LiteLLM/Portkey/Helicone.
- [x] Design commits to core-first Go implementation under `internal/llmguard`.
- [x] Input guard scope includes API keys, GitHub tokens, AWS keys, emails, card-like numbers, phones, base64 secrets, and simple split secrets.
- [x] Output guard scope includes generated secrets, prompt/system prompt disclosure attempts, suspicious URLs, and shell-command-like text.
- [x] Audit contract stores redacted findings, verdicts, token usage, estimated cost, and SDP provenance without raw secrets.
- [x] MVP test corpus includes at least 10 deterministic cases and records known misses.
- [x] HTTP proxy, rate limiting, and live providers are framed as demo/integration surfaces after the core contract.
- [x] Streaming support, live provider calls, direct Beads writes, signed/queryable audit storage, and full call-site adoption are explicitly excluded from the first implementation workstream.
- [x] Workstream review evidence records a clean-context `pi` review and the author resolution notes before implementation planning starts.

## Out of Scope

- Implementing `internal/llmguard`.
- Adding HTTP server code.
- Adding live OpenAI/Anthropic/OpenRouter calls.
- Claiming complete secret detection or complete prompt-injection protection.
