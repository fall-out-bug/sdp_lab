# 00-166-08: Codex and Pi gateway surfaces implementation

Feature: F166 (sdplab-mp83)

## Goal

Turn `sdp-llm-gateway` from a simplified demo proxy into a usable local guard
boundary for Codex and Pi. Implement the two harness-facing OpenAI-compatible
surfaces specified by `00-166-07`: Codex `/v1/responses` SSE and Pi
`/v1/chat/completions` streaming.

## Beads

- sdplab-lhn5

## Scope Files

- `cmd/sdp-llm-gateway/main.go`
- `cmd/sdp-llm-gateway/main_test.go`
- `internal/llmguard/gateway.go`
- `internal/llmguard/types.go`
- `docs/plans/2026-05-03-f166-runtime-llm-guard-gateway-design.md`
- `docs/reviews/2026-05-04-f166-workstream-readiness.md`
- `docs/workstreams/backlog/00-166-08.md`

## Ownership

This workstream owns HTTP request/response compatibility and gateway wiring. It
must not implement the local classifier internals beyond calling the existing or
future classifier hook when available. Classifier implementation belongs to
`00-166-09`. If this workstream must touch shared `internal/llmguard` types, keep
the change additive and document it in tests so `00-166-09` can consume it
without rewriting endpoint code.

## Acceptance Criteria

- [ ] Pre-work check records whether `internal/llmguard/gateway.go` already
  supports buffered output scanning for streaming-shaped responses; if not, the
  workstream adds a buffered streaming wrapper before endpoint routes release
  assistant output.
- [ ] `POST /v1/responses` accepts a Codex-style Responses request, runs guard
  policy before upstream egress, and emits valid SSE with terminal
  `response.completed`.
- [ ] Codex-style blocked input returns a Responses-shaped safe stream and never
  calls the fake upstream.
- [ ] Codex-style clean input calls the fake upstream exactly once and preserves
  a valid Responses SSE shape back to the client.
- [ ] `POST /v1/chat/completions` accepts a Pi-style request with `stream: true`
  and `stream_options.include_usage: true`.
- [ ] Pi-style blocked input returns a valid Chat Completions response matching
  the request stream mode and never calls the fake upstream.
- [ ] Pi-style clean input calls the fake upstream exactly once and returns a
  valid Chat Completions stream.
- [ ] Streaming output follows the F166 conservative policy: buffer upstream
  output, scan assistant text, then emit harness-shaped output; do not raw-pass
  provider chunks before output guard.
- [ ] Audit events include harness, endpoint surface, requested model, upstream
  model, verdict state, stream requested/returned, upstream-called yes/no,
  feature/workstream/beads metadata, and no raw secrets.
- [ ] CI tests use fake upstreams only and do not require live provider keys.

## Out of Scope

- Live provider smoke against paid providers.
- Full LiteLLM-compatible provider matrix.
- Tool-call streaming support beyond clear unsupported-shape errors.
- Local classifier implementation; see `00-166-09`.
