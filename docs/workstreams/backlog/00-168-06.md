# 00-168-06: Operator-facing quality report UX

Feature: F168 (sdplab-o8gk)
Design reference: [F168 design](../../plans/2026-05-13-f168-onboarding-quality-taxonomy-design.md)

## Goal

Design and implement the operator-facing report that shows onboarding truth and
quality-axis status without hiding uncertainty.

## Scope Files

- `cmd/sdp/`
- `internal/`
- `docs/reference/`
- `docs/runbooks/onboarding-downstream-repo.md`

## Beads

- primary: sdplab-f16806

## Acceptance Criteria

- [ ] The report separates blocking failures, warnings, evidence-only checks, `not_assessed`, and `cannot_verify`.
- [ ] The report tells the operator which command or reviewer produced each result.
- [ ] The report points to the next actionable fix or bead for each failing axis.
- [ ] The UX is useful from a fresh onboarding path, not only from an internal maintainer session.

## Out of Scope

- Building a dashboard.
- Adding visual UI beyond CLI/report output.
