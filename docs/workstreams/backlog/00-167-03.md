# 00-167-03: F167 Agentloop Security Gate Integration

Feature: F167 (sdplab-xe5c)
Phase: Pilot Evidence & Spec Quality
Status: Backlog

## Goal

Integrate the security verdict gate into SDP's runtime execution path after
green tests and before commit/promotion-ready state. Critical/High findings
return the loop to Build with actionable feedback; Medium/Low findings are
visible warnings that do not block progress.

## Acceptance Criteria

- [ ] Security gate runs only after test evidence is `passed`.
- [ ] Gate insertion point is the synchronous Build completion pre-transition path: after Build test evidence passes and before transition toward Review or any commit/promotion-ready state.
- [ ] Critical/High findings block promotion and produce Build feedback with file, line, title, and suggested fix.
- [ ] Medium/Low findings create warning evidence and allow promotion.
- [ ] Clean verdict allows promotion.
- [ ] Provider/sanitizer/evidence failure escalates rather than passing silently.
- [ ] Escalation creates an operator-visible recovery decision: retry security review, roll back to Build, approve with recorded risk if policy allows, or stop.
- [ ] Direct transition tests prove Build cannot advance through the F167-protected path when the gate returns block or escalated.
- [ ] Gate output is persisted as evidence and linked to the active feature/workstream where available.
- [ ] Unit tests cover pass, warn, block, and escalated paths with stub gateway/reviewer.
- [ ] Targeted agentloop/pireview tests pass without live provider credentials.

## Out of Scope

- Adding a sixth FSM phase unless the narrow gate cannot meet acceptance.
- Intercepting manual `git commit`.
- Making live provider availability mandatory in normal CI.
