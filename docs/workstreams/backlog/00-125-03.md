# 00-125-03: Operate Planning and Skill Consolidation

Feature: F125 (Toolkit UX — intent-routed skills over composable tools)

## Goal

Finish the consolidation so planning sits inside `@operate`, and build/fix/review behavior no longer depends on a sprawling flat skill taxonomy.

## Beads

- sdplab-w6nu

## Scope Files

- `skills/build.md`
- `skills/fix.md`
- `skills/review.md`
- `skills/operate.md`
- `docs/reference/skills.md`
- `docs/reference/commands.md`

## Acceptance Criteria

- [ ] planning is represented as `@operate --mode plan`, not a standalone skill
- [ ] `@build`, `@fix`, and `@review` have clear boundaries and mode parameters
- [ ] `tdd`, `guard`, and `go-modern` are documented as embedded practices or policies, not primary skill entry points
- [ ] docs stop advertising duplicate or overlapping user entry points
- [ ] consolidated skills still respect existing brownfield and operator workflows

## Out of Scope

- deprecation warnings
- migration evals
- MCP prompt export

## Implementation Notes

- Design source: `docs/plans/2026-04-13-sdp-skill-architecture-design.md`
- The goal is not fewer files at any cost. The goal is fewer user choices with clearer behavior.
