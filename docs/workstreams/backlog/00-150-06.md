# 00-150-06: Coverage policy rebaseline by maturity

Feature: F150 (Product Layering And Release Readiness)

Design reference: [2026-04-27-f150-product-layering-release-readiness-design.md](../../plans/2026-04-27-f150-product-layering-release-readiness-design.md)

## Goal

Align coverage expectations with product maturity instead of enforcing contradictory blanket targets.

## Beads

- sdplab-q2cb (F150-06: rebaseline coverage policy by maturity)

## Scope Files

- `docs/reference/maturity-matrix.md`
- `docs/reference/ci-gates-map.md`
- `.github/workflows/ci.yml`
- `scripts/quality-metrics.sh`
- `Makefile`
- `.sdp/metrics/coverage.txt` if baseline policy changes require it

## Acceptance Criteria

- [ ] Happy-path coverage target is documented as `>=80%`.
- [ ] GA component target is documented as `>=60%`.
- [ ] Beta component target is documented as `>=50%`.
- [ ] Experimental components are not blocking coverage gates.
- [ ] Coverage reports state the denominator: package, command, product surface, or happy-path scenario.

## Out of Scope

- Raising every package to 80%.
- Deleting low-coverage experimental code.
- Treating coverage percentage as a substitute for behavior tests.
