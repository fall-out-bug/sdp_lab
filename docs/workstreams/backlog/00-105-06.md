Implement the Python ecosystem extractor using tree-sitter queries for import resolution, dependency parsing from requirements.txt/pyproject.toml, and Flask/FastAPI/Django route detection.

## Acceptance Criteria

- [ ] tree-sitter queries extract top-level import statements with 60-70% accuracy
- [ ] Import resolution handles: `import X`, `from X import Y`, relative imports (`from . import`)
- [ ] requirements.txt parsed (pinned and unpinned versions)
- [ ] pyproject.toml parsed (PEP 621 [project.dependencies], Poetry, Flit sections)
- [ ] setup.py basic dependency extraction (install_requires list)
- [ ] Flask detection: @app.route, Blueprint registration
- [ ] FastAPI detection: APIRouter, @app.get/post decorators, Pydantic model references
- [ ] Django detection: urlpatterns, apps.py AppConfig, models.py model classes
- [ ] Known blind spots documented: importlib, sys.path manipulation, conditional imports, notebook imports

## Out of Scope

- Notebook (.ipynb) import analysis
- Runtime import resolution (sys.path manipulation)
- Conditional import handling (try/except import blocks)
- importlib.import_module dynamic loading

## Implementation Notes

- From section 1.5: Python uses tree-sitter + requirements.txt/pyproject.toml with 60-70% import accuracy
- Strengths: top-level imports, package structure, Flask/FastAPI/Django route detection
- Blind spots: importlib, sys.path manipulation, conditional imports, notebook imports
- tree-sitter query for Python imports: match `import_statement` and `import_from_statement` nodes
- Flask route extraction: find `decorated_definition` with `attribute` matching `route` on `app` or `Blueprint`
- FastAPI route extraction: find decorators matching get/post/put/delete/patch on APIRouter or FastAPI instances
- Django patterns: scan for `urlpatterns` list assignments, `class *Config(AppConfig)`, and Django model fields
- For pyproject.toml, consider using pelletier/go-toml for parsing
- Accuracy is lower than Go due to Python's dynamic nature — document this honestly
