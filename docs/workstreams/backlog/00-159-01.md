## Acceptance Criteria

- [ ] Per-competitor section covers:
  - What they do (1–2 sentences)
  - Where they win (ICP, deal size, deployment model)
  - Where SDP differentiates (gaps they leave)
- [ ] SDP differentiation is grounded in observable, defensible claims:
  - Agent-neutral cross-tool evidence (vs single-vendor lock-in)
  - Override trail + governed decision record (accountability layer none of them offer)
  - Operator Mode stateful orchestration (vs stateless review)
  - Toolbox + IIP family (composable, not platform-all-or-nothing)
- [ ] Position statement: ≤3 sentences, buyer-readable
- [ ] Top 3 buying objections from the target ICP
- [ ] Top 3 SDP rebuttals (evidence-backed, not marketing)
- [ ] Replacement-risk section: acknowledges 70–85% SDP functions can be replaced today by GitHub + Spec Kit/Kiro + Codex/Claude + CodeRabbit/Sonar; explains the 15–30% defensible moat
- [ ] Battle card is ≤1 page, printable
