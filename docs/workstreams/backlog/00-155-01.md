# 00-155-01: Evidence persistence decision artifact

Feature: F155 (sdplab-xdg9)
Parent bead: sdplab-xdg9.1

## Goal

Make an explicit, documented decision on the storage backend for SDP evidence so this choice does not get unwound after Schema v1 is frozen.

## Beads

- sdplab-xdg9.1

## Scope Files

- `docs/strategy/evidence-persistence-architecture.md` — decision artifact

## Candidates to Evaluate

| Backend | Notes |
|---------|-------|
| Git LFS | Append-only history, audit-friendly, no infra |
| Object storage (S3/GCS) | Scalable, external dependency, privacy controls |
| Local SQLite | Zero-infra, single-node, not suitable for multi-team |
| MCP server | Agent-native, streaming replay, new dependency |

## Acceptance Criteria

- [ ] Evaluation matrix covers all 4 candidates across:
  - Durability (data loss on failure)
  - Append-only log support (tamper evidence)
  - Replay / rebuild capability
  - Storage cost at pilot scale (100 PRs/week)
  - Privacy / redaction support
  - Backup and restore procedure
  - Compliance posture (SOC2 relevance)
  - Ops complexity at early stage
- [ ] Separate recommendation for: Operator Mode surface vs sdp-pr-gate surface
- [ ] Retention policy decision: how long evidence is kept per passport
- [ ] Privacy decision: PII handling in evidence payloads
- [ ] Decision clearly states which schema fields touch storage (tie to 00-151-01)
- [ ] ADR format (context / decision / consequences)

## Out of Scope

- Implementation of the chosen backend
- Migration tooling
