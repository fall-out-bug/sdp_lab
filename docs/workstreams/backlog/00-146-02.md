# 00-146-02: Stitchers — Enum / JSON / TOON

Feature: F146 (Inference Decomposition Framework)

Design reference: [2026-04-26-f146-inference-decomposition-design.md §3 F146-02](../../plans/2026-04-26-f146-inference-decomposition-design.md)

## Goal

Ship the three built-in inter-stage `Stitcher` implementations enforcing strict format on stage outputs:
- `EnumStitcher` for closed-set classification values (cheapest path, e.g. `pass|warn|fail`).
- `JSONStitcher` for structured extraction (reuses F144 schema-validation patterns).
- `TOONStitcher` for token-optimized aggregate output (target 40 %+ token saving vs JSON for tabular data).

## Acceptance Criteria

- [ ] `Stitcher` interface with `Name() string`, `Validate(out any) error`, `Marshal(out any) (string, error)`.
- [ ] `EnumStitcher.Validate` — typed error if value not in allowed list; allowed list passed at construction; comparison case-sensitive.
- [ ] `EnumStitcher.Marshal` — `string(value)` (no quoting / wrapping).
- [ ] `JSONStitcher.Validate` — schema validation; typed error includes JSON path of first violation.
- [ ] `JSONStitcher.Marshal` — `json.Marshal` with indent for human-readability in evidence; round-trip property — `Marshal → parse → Validate` is no-op.
- [ ] `TOONStitcher.Marshal` — header `# col1 | col2 | col3` then row-per-record `v1 | v2 | v3`; single-record inline fallback `col1=v1, col2=v2`.
- [ ] `TOONStitcher.Validate` — parses string back into typed slice/map; column types matched against registered `TOONColumn` schema.
- [ ] TOON edge cases: nested objects → error (`unsupported in v1`), null cells → empty between separators, empty rows → header-only output valid.
- [ ] Cross-stitcher property test (table-driven): for each (stitcher, valid_input) pair, `out := Marshal(input); parsed := parseback(out); err := Validate(parsed)` — `err` is nil.
- [ ] `BenchmarkStitcher_Marshal_TOON` token count ≤ `BenchmarkStitcher_Marshal_JSON` × 0.60 on tabular fixture (≥ 40 % saving target).
- [ ] Coverage of stitcher files ≥ 85 %.
- [ ] README extended with examples; TOON-vs-JSON saving documented with actual numbers from bench output.
- [ ] `go build ./...` and `go vet ./...` clean.

## Out of Scope

- Nested object/array support in TOON (v1 limitation).

- Per-stage stitcher application order vs confidence/cascade (→ 00-146-03).
