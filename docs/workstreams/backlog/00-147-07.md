# 00-147-07: ws-verdict micro-first integration (default=on)

Feature: F147 (MicroFirst Inference Tier)

Design reference: [2026-04-27-f147-microfirst-tier-design.md §3 F147-07](../../plans/2026-04-27-f147-microfirst-tier-design.md)

## Goal

Integrate `WsVerdictMicro` (00-147-02) as the micro-side of `WithEscalation` (00-147-01) wrapping the F146-04 extract stage. Default behaviour: micro-first **on**. Kill-switch: `--no-microfirst` flag в `cmd/sdp-ws-verdict-validate`.

## Beads

- sdplab-itzf (historical F147 anchor; leaf Beads were not preserved)

## Scope Files

- `internal/inference/decompose/adapters/wsverdict/pipeline.go` — modify. `NewWSVerdictPipeline(client, opts)` принимает `MicroFirst bool` в opts. По default true. Когда true — оборачиваем extract stage в `WithEscalation(microfirst.NewWsVerdictMicro(...), originalExtract, cfg)`.
- `internal/inference/decompose/adapters/wsverdict/pipeline_test.go` — extend. Cases:
  - default (microfirst=true): clean-pass/clear-fail fixture'ы — extract stage не зовёт LLM (TokensIn=0).
  - microfirst=false: байт-в-байт идентично F146-04 baseline.
  - ambiguous fixture: extract escalated, llm called.
- `cmd/sdp-ws-verdict-validate/main.go` — modify. Добавить `--no-microfirst` flag (default=false → microfirst on). Передавать в opts.

## Acceptance Criteria

- [ ] `NewWSVerdictPipeline` API расширен `Options{MicroFirst bool}`; defaults `MicroFirst=true`.
- [ ] При `MicroFirst=true` extract stage обёрнут `WithEscalation`.
- [ ] Fixture clean-pass: `extract.Trace.TokensIn == 0` (LLM not called).
- [ ] Fixture clear-fail: `extract.Trace.TokensIn == 0`.
- [ ] Fixture ambiguous: `extract.Trace.Attempts == 2`, `extract.Trace.TokensIn > 0`.
- [ ] `--no-microfirst` flag → байт-в-байт regression равно F146-04 (golden output).
- [ ] Coverage ≥ 80%.
- [ ] `go build ./...` and `go vet ./...` clean.

## Out of Scope

- Other stages (classify, aggregate) micro-first wrapping — explicit non-goal in v1.
- Renaming F146-04 flags (`--decompose` остаётся как был).
