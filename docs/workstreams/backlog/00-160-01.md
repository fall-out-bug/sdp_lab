# 00-160-01: Procurement-ready install profile artifact

Feature: F160 (sdplab-mipu)
Parent bead: sdplab-mipu.1

## Goal

Produce a procurement install profile that lets a manager-buyer complete a security review without escalating to the security team. Required before any regulated-industry pilot.

## Beads

- sdplab-mipu.1

## Scope Files

- `docs/strategy/procurement-install-profile.md` — main artifact
- `docs/strategy/sla-template.md` — SLA template
- `docs/strategy/dpa-answers.md` — Data Processing Agreement answers template

## Acceptance Criteria

- [ ] **Permissions section**: scoped GitHub App permissions listed (read-only access only at install; write permissions enumerated with justification)
- [ ] **No-egress mode**: documented configuration for air-gapped or no-external-network installs
- [ ] **Data residency**: where evidence data is stored, options for EU/US/self-hosted
- [ ] **SOC2 posture**: current state (Type I / Type II / self-assessed), roadmap
- [ ] **SLA template**: uptime commitment for pilot, incident response SLA, escalation path
- [ ] **Indemnification template**: stub for standard vendor indemnification language
- [ ] **DPA answers**: standard vendor-onboarding questions answered (controller/processor roles, sub-processors list, BCP/DR summary, data deletion on offboarding)
- [ ] **Procurement friction section**: known blockers (no billing in tool, legal entity, insurance), workarounds for each
- [ ] Document is reviewable by a procurement / security team without SDP-specific context

## Out of Scope

- Actual SOC2 audit
- Legal review of indemnification (flag for legal counsel)
- Billing infrastructure
