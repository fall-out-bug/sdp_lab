# 00-105-07: Java/Kotlin Extractor (tree-sitter)

Feature: F105 (AI Architect)

## Goal

Build the Java/Kotlin ecosystem extractor using tree-sitter queries for import analysis, Maven/Gradle module structure, and Spring Boot annotation extraction for @RestController, @Service, @Repository patterns.

- sdplab-tx1h: historical shipped feature anchor for F105 (PR #86)

## Acceptance Criteria

- [ ] tree-sitter queries extract Java import statements with 70-80% accuracy
- [ ] Maven module graph constructed from parent POM and <modules> sections
- [ ] Gradle multi-project structure parsed from settings.gradle include directives
- [ ] Spring Boot annotations detected: @RestController, @Service, @Repository, @Component, @Configuration, @Bean
- [ ] Controller route extraction: @RequestMapping, @GetMapping, @PostMapping mapped to endpoint paths
- [ ] Package structure analysis maps com.company.module.* hierarchies to logical components
- [ ] Kotlin support: top-level functions, extension functions, companion objects, data classes
- [ ] Known blind spots documented: reflection (Class.forName), runtime DI wiring, annotation processors, Kotlin DSL configs

## Out of Scope

- Reflection-based dependency resolution (Class.forName, ServiceLoader)
- Runtime DI wiring analysis
- Annotation processor output tracking
- Kotlin DSL build script evaluation (use regex fallback for build.gradle.kts)

## Implementation Notes

- From section 1.5: Java/Kotlin uses tree-sitter + Maven/Gradle analysis with 70-80% import accuracy
- Strengths: package imports, Spring Boot annotations, Maven module graph
- Blind spots: reflection, runtime DI wiring, annotation processors, Kotlin DSL configs
- tree-sitter query for Java imports: match `import_declaration` nodes, extract package paths
- Spring annotation extraction: scan for `marker_annotation` and `annotation` nodes matching Spring stereotypes
- Maven module graph: parse pom.xml for <parent>, <modules>, and <dependency> sections — use xml parsing library
- Gradle settings: parse settings.gradle for `include` directives to identify subprojects
- Java package hierarchy (com.company.module.sub) maps naturally to component boundaries
- Kotlin support shares tree-sitter infrastructure but adds language-specific patterns
