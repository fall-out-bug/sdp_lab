# 00-150-04: Experimental isolation from release builds

Feature: F150 (Product Layering And Release Readiness)

Design reference: [2026-04-27-f150-product-layering-release-readiness-design.md](../../plans/2026-04-27-f150-product-layering-release-readiness-design.md)

## Goal

Keep experimental code available in the lab while preventing it from becoming part of the stable formula or release build by accident.

## Beads

- sdplab-5r4x (F150-04: isolate experimental code from release builds)

## Scope Files

- `.goreleaser.yml`
- `cmd/`
- `internal/`
- `docs/reference/product-surface.md`
- `docs/reference/maturity-matrix.md`
- release/build scripts as needed

## Acceptance Criteria

- [ ] Release build includes only the selected stable surface.
- [ ] Experimental commands/packages are excluded by explicit build tags, release allowlist, or documented lab-only boundary.
- [ ] Local developer builds still have a documented way to run experiments.
- [ ] No tests are deleted to make isolation pass.
- [ ] `scripts/check-release-surface.sh` or equivalent catches accidental release-surface drift.

## Out of Scope

- Deleting experimental packages.
- Productizing agentloop or model gateway.
- Homebrew formula publishing.
