# 00-105-01: Security Filter + Pipeline Hardening

Feature: F105 (AI Architect)

## Goal

Implement the full security pipeline for AI Architect: secret scrubbing, prompt injection defense, TOCTOU-safe file access, output sanitization, and error recovery. This is a non-negotiable prerequisite for all LLM integration.

**Source spec:** `docs/plans/2026-04-10-ai-architect-impl-security.md` (7 rounds of council review, unanimously approved)

## Acceptance Criteria

### Secret Scrubbing (Spec Section 2)
- [ ] ScrubSecrets covers: AWS keys, GitHub tokens, Stripe keys, JWT tokens, Slack tokens, connection strings, private keys, OpenAI keys
- [ ] Compiled gitleaks rules loaded from embedded config at init
- [ ] HighEntropyCheck (>4.5 bits/char, length>=20) with EXACT allowlist patterns: UUID, sha256/512 integrity, hex hashes
- [ ] Output-side ScrubSecrets: JSON-aware (parses JSON, scrubs string values only, never keys)
- [ ] Redaction format: `[REDACTED_<TYPE>]`
- [ ] Audit logging: redaction counts per type, never content

### Prompt Injection Defense (Spec Section 1)
- [ ] HEX32 delimiters generated via `crypto/rand.Read()` (NOT math/rand)
- [ ] SanitizeForLLM strips instruction-like patterns (defense-in-depth only)
- [ ] System prompt includes untrusted-content instruction
- [ ] Delimiter changes per call (128-bit CSPRNG, ~3.4e38 combinations)

### Path Traversal (Spec Section 3)
- [ ] ValidatePath uses `unix.Openat()` with `O_RDONLY | O_NOFOLLOW`
- [ ] Repo root opened first for dirfd anchor
- [ ] Returns `io.ReadSeekCloser` interface (unexported ValidatedFile concrete type)
- [ ] No path-dependent operations after validation (no Name(), no Readdir())
- [ ] `runtime.SetFinalizer` backup for cleanup; Close() clears finalizer
- [ ] Platform: Linux + macOS only; build tag `//go:build !windows`

### Output Sanitization (Spec Section 4)
- [ ] SanitizeField: gomarkdown with `FlagsNone` (no raw HTML passthrough) -> custom bluemonday policy
- [ ] Custom policy: allows only b/i/em/strong/a/p/br/ul/ol/li/code/pre; URL schemes http/https only; no script/style/iframe/on* attributes
- [ ] SanitizeOutput: recursive traversal of all JSON string values
- [ ] Persistence contract: LLMEnrichment fields store sanitized HTML
- [ ] Policy instantiated once in init(), immutable, thread-safe

### Pipeline Integration (Spec Section 4)
- [ ] Dual pipeline: INPUT (ScrubSecrets->SanitizeForLLM->WrapForLLM->API) and OUTPUT (ScrubSecrets(output)->JSON parse->SanitizeOutput)
- [ ] Per-request isolation: fresh delimiter, fresh scrub context, no shared caches
- [ ] SecureEnricher interface enforces mandatory pipeline order

### Error Recovery (Spec Section 6)
- [ ] RetryConfig: 3 retries, exponential backoff 1s/2s/4s with +/-20% jitter
- [ ] CircuitBreaker: 5 consecutive failures -> 30s cooldown, per-provider scope
- [ ] EnrichmentResult: Completed bool, Enrichment map (validated only), Failed []EnrichmentError
- [ ] EnrichmentError: NodeID, Stage, Retriable flag
- [ ] Idempotency: requestID UUID per enrichment request

### General
- [ ] No test fixture contains real secrets
- [ ] Adversarial test vectors: OWASP XSS patterns, prompt injection patterns, path traversal vectors

## Out of Scope

- Network-level LLM proxy or middleware
- Encryption at rest for audit logs
- Integration with external secret vaults (Vault, AWS Secrets Manager)
- Windows support for ValidatePath
- RAG-based context retrieval

## Implementation Notes

- This workstream is the largest and most critical — all other LLM workstreams depend on it
- The security spec survived 7 rounds of multi-model council review with unanimous convergence
- Key council-validated decisions: null byte delimiters, dual pipeline, openat+dirfd, custom bluemonday (not UGCPolicy), field-level sanitization (not raw JSON)
- New dependencies: `github.com/microcosm-cc/bluemonday`, `github.com/gomarkdown/markdown`, `golang.org/x/sys/unix`
