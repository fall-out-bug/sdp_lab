# 00-105-01: Security Filter Hardening

Feature: F105 (AI Architect)

## Goal

Implement the SecurityFilter that scrubs secrets and PII from codebase profiles before any data leaves the local machine. This is a non-negotiable prerequisite for all LLM integration.

## Beads

- (will be created when workstream is claimed)

## Scope Files

- `internal/architect/security/filter.go` — SecurityFilter implementation
- `internal/architect/security/filter_test.go` — pattern coverage tests
- `internal/architect/security/pii.go` — PII scrubbing logic
- `internal/architect/security/audit.go` — LLM call audit log
- `internal/architect/security/security_test.go` — integration tests

## Acceptance Criteria

- [ ] SecretPatterns cover AWS keys, API tokens, passwords, connection strings, JWT secrets, private keys
- [ ] PIIScrubber hashes internal package prefixes (`com.company.secret` -> `pkg.<hash>`) and anonymizes file paths with usernames
- [ ] AllowExternalLLM defaults to false; cloud LLMs only accessible with explicit `--allow-external-llm` flag
- [ ] Every LLM call is logged to audit file with sanitized input hash, timestamp, and token count
- [ ] Local LLM path configured as primary (self-hosted models like Llama, CodeLlama)
- [ ] Unit tests achieve >90% coverage on secret pattern matching
- [ ] No test fixture contains real secrets — all test patterns are synthetic

## Out of Scope

- Network-level LLM proxy or middleware
- Encryption at rest for audit logs
- Integration with external secret vaults (Vault, AWS Secrets Manager)

## Implementation Notes

- From design spec section 1.4: SecurityFilter struct has SecretPatterns ([]regexp.Regexp), PIIScrubber (func(string) string), and AllowExternalLLM (bool, default false)
- Secret detection targets env vars, config files, and connection strings — hash or redact before LLM
- Audit log records every LLM call with sanitized input hash for compliance
- Local LLM is the default path; cloud LLMs require explicit opt-in via flag
- This is flagged "Critical" in the design decisions table — 7/7 models agreed it is non-negotiable
- Consider using well-known regex libraries for secret patterns (e.g., shhgit, truffleHog patterns) as reference
- PII scrubbing must handle: internal package names, file paths with `/home/username/` or `/Users/name/`, email addresses in comments, author names from git history
