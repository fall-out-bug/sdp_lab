# 00-125-01: Intent Contract and Alias Map

Feature: F125 (Toolkit UX — intent-routed skills over composable tools)

## Goal

Define the five-intent contract, the old-skill alias map, and the explicit acceptance boundaries so the UX can shrink without becoming vague.

## Beads

- sdplab-rj0v

## Scope Files

- `skills/`
- `docs/reference/skills.md`
- `docs/reference/agent-catalog.md`
- `docs/plans/2026-04-13-sdp-skill-architecture-design.md`

## Acceptance Criteria

- [ ] the five intent entry points are explicit: `understand`, `build`, `fix`, `review`, `operate`
- [ ] legacy skill names have a documented routing or deprecation path
- [ ] each intent has clear modes and input expectations
- [ ] docs stop implying that `@landscape` or `@plan` are separate first-class concepts
- [ ] acceptance boundaries explain what stays a practice or policy instead of a skill

## Out of Scope

- tool composition logic
- documentation cutover
- MCP prompt packaging

## Implementation Notes

- Design source: `docs/plans/2026-04-13-sdp-skill-architecture-design.md`
- This is a UX contract. If the routing rules are muddy, later implementation will regress into another flat list.
