# 00-145-13: LimitsCache — background poller + response-header adapter

Feature: F145 (Multi-Provider Dispatch Matrix & Confidence-Driven Cascade)

Design reference: [2026-04-26-f145-multi-provider-dispatch-cascade-design.md §4.5](../../plans/2026-04-26-f145-multi-provider-dispatch-cascade-design.md)

## Goal

Реализовать `LimitsCache` для Provider'ов: bootstrap через poller, далее обновление из response headers после каждого harness invoke. Hot-path Route не должен блокироваться на HTTP-вызовах.

## Beads

- (assigned during epic creation)

## Scope Files

- `internal/dispatch/harness/limits_cache.go` — new. `LimitsCache struct{ pollers map[string]*time.Ticker; cache sync.Map; ttl time.Duration }`. Methods: `Start(ctx, providers []Provider)`, `Stop()`, `Get(provider string) *Limits`, `UpdateFromHeaders(provider string, hdrs http.Header)`.
- `internal/dispatch/harness/limits_cache_test.go` — new. Tests: poller обновляет cache; Get возвращает latest; UpdateFromHeaders переопределяет poller-data; concurrent Get/Update thread-safe; TTL expiration.
- `internal/dispatch/harness/limits_cache_doc.md` — new. Документация: TTL=30s default, header priority over poller, что делать если provider не поддерживает headers.

## Acceptance Criteria

- [ ] `LimitsCache.Start` запускает per-provider poller (mock в test через injectable clock).
- [ ] `Get` thread-safe (race detector clean).
- [ ] `UpdateFromHeaders` имеет приоритет над poller cache (последняя запись wins).
- [ ] `Stop()` корректно выключает все poller'ы (no goroutine leak в test).
- [ ] Hot-path benchmark: `Get` p99 < 100µs (sync.Map read).
- [ ] go build, go test, go test -race ./internal/dispatch/harness/..., go vet clean.

## Out of Scope

- Wire-up в Router/CascadingInvoker — это вызов `LimitsCache.Get` уже работает через существующий `limits map[string]*harness.Limits` интерфейс. WS 14 проверяет integration.
