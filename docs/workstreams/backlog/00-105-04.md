# 00-105-04: InfraExtractor

Feature: F105 (AI Architect)

## Goal

Extract architecture signals from infrastructure and CI configuration files: Dockerfiles, docker-compose, Kubernetes manifests, Terraform plans, and CI pipeline configs. Detect module boundaries across build systems.

## Beads

- (will be created when workstream is claimed)

## Scope Files

- `internal/architect/extract/infra.go` — InfraExtractor main implementation
- `internal/architect/extract/infra_test.go`
- `internal/architect/extract/docker.go` — Dockerfile and docker-compose parsing
- `internal/architect/extract/k8s.go` — Kubernetes manifest parsing
- `internal/architect/extract/terraform.go` — Terraform HCL parsing
- `internal/architect/extract/ci.go` — CI config parsing (GitHub Actions, GitLab CI, Jenkinsfile)
- `internal/architect/extract/module_boundary.go` — module boundary detection across build systems
- `internal/architect/extract/module_boundary_test.go`

## Acceptance Criteria

- [ ] Dockerfile parser extracts: base images, exposed ports, ENTRYPOINT/CMD, environment variables, COPY/ADD targets
- [ ] docker-compose parser extracts: services, networks, volumes, environment variables, dependency links between services
- [ ] Kubernetes manifest parser handles: Deployments, Services, ConfigMaps, Ingress, Namespaces, and identifies deploy units
- [ ] Terraform parser identifies: resources, providers, modules, variable references, output dependencies
- [ ] CI config parser extracts: build stages, deployment targets, environment triggers
- [ ] Module boundary detection for: Maven modules (pom.xml parent/modules), Gradle projects (settings.gradle include), npm workspaces (package.json workspaces), Go cmd/ directories
- [ ] Infra signals feed directly into C4 L1 (system context) and L2 (container) generation
- [ ] All environment variables and secrets passed through SecurityFilter before profile inclusion

## Out of Scope

- Runtime infrastructure discovery (cloud API calls)
- Helm chart templating resolution
- Pulumi program analysis
- Ansible playbook parsing

## Implementation Notes

- From section 2.1: L1 System Context comes from InfraExtractor — Docker, Terraform, CI, sanitized env refs
- L2 Container comes from deploy units: docker-compose services, k8s deployments, workspace members
- From section 4.2: Monorepo support — `.sdp/architecture/` distributed per bounded context to avoid merge conflicts
- Module boundary detection maps build system units to CodebaseProfile containers
- From section 1.1: InfraExtractor is part of Phase 1 deterministic extraction (pure Go, no LLM)
- Consider using existing Go libraries: docker/cli for compose parsing, hashicorp/hcl for Terraform, k8s.io/apimachinery for K8s manifests
- Sanitize all environment variable values through SecurityFilter — never include actual values in profile
