# 00-121-07: Data Integrity Fixes

Feature: F121 (Toolkit Metrics — git-derived process health)

## Goal

Fix 2 blocking P1 findings from round-2 review: P95 percentile integer truncation produces wrong values, and git errors silently discarded producing partial reports with no failure indication. Also fix release quality window boundary double-counting.

## Review Findings Addressed

| # | Severity | Source | Finding |
|---|----------|--------|---------|
| 1 | P1 | SRE | P95 branch lifetime index uses integer truncation: `lifetimes[len(lifetimes)*95/100]` returns wrong value for repos with <100 branches |
| 2 | P1 | SRE | collectTags/collectBranches/countMerges silently discard gitCmdErr errors, returning nil/0 with no failure indication |
| 3 | P2 | QA | Release quality double-counts commits at window boundaries (commit AT next tag date included in both windows) |

- [x] Release quality uses `!c.Date.After(windowEnd)` → `c.Date.Before(windowEnd)` to avoid double-counting at tag boundaries (or equivalent fix)
