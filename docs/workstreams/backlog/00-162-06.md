# 00-162-06: Cursor, Pi, and Kilo harness profiles and smoke contracts

Feature: F162 (sdplab-wuaa)
Parent bead: sdplab-wuaa.6

## Goal

Promote Cursor, Pi, and Kilo into explicit F162 packaging targets with
capability profiles, native entrypoints, launch shapes, and smoke tests.

## Beads

- sdplab-wuaa.6

## Scope Files

- `docs/reference/harness-integration.md`
- `sdp.manifest.yaml`
- `internal/manifest/schema.json`
- `internal/adapters/templates/`
- `configs/dispatch.example.yaml`

## Acceptance Criteria

- [ ] Cursor profile names its entrypoints (`.cursorrules`, `.cursor/rules/*.mdc`), invocation shape, and minimum smoke test.
- [ ] Pi profile names the exact Pi runtime/CLI, project instruction support if any, fallback launcher-only path if needed, and minimum smoke test.
- [ ] Kilo profile names its entrypoints (`AGENTS.md`, `CLAUDE.md`, `kilo.jsonc`, `.kilocodemodes`, `.kilo/agents/*.md`, `.kilo/rules-*`), invocation shape, and minimum smoke test.
- [ ] Each profile declares whether it is `green`, `experimental`, or `blocked`, with the reason visible in generated parity docs.
- [ ] F162 implementation workstreams can consume these profiles without re-deciding harness semantics.

## Out of Scope

- Full adapter implementation for the three profiles.
- Claiming dispatch parity before smoke tests pass.
