# 00-105-09: SQL Analysis

Feature: F105 (AI Architect)

## Goal

Build the SQL analysis module for data architecture signal extraction: DDL parsing, migration file analysis, ORM model correlation, PII column detection, and table cluster inference for data domain discovery.

- (will be created when workstream is claimed)

## Scope Files

- `internal/architect/extract/sql/extractor.go` — SQLExtractor main implementation
- `internal/architect/extract/sql/extractor_test.go`
- `internal/architect/extract/sql/ddl.go` — DDL parser (CREATE TABLE, ALTER TABLE, CREATE VIEW)
- `internal/architect/extract/sql/ddl_test.go`
- `internal/architect/extract/sql/migration.go` — migration file ordering and analysis (Flyway, Alembic, Prisma)
- `internal/architect/extract/sql/orm.go` — ORM model correlation (SQLAlchemy, Django, GORM, JPA, Prisma)
- `internal/architect/extract/sql/pii.go` — PII column detection

## Acceptance Criteria

- [ ] DDL parser extracts: table definitions (name, columns, types), views, indexes, stored procedures
- [ ] Foreign key relationships identified between tables for C4 edge generation
- [ ] Migration directories detected: migrations/, db/migrate/, alembic/versions/ — ordered by timestamp/name
- [ ] ORM model correlation maps: SQLAlchemy models, Django models, GORM structs, JPA entities, Prisma schema
- [ ] PII column detection flags: email, ssn, phone, address, birth_date, first_name, last_name, passport, credit_card patterns
- [ ] Table clustering groups related tables into inferred bounded contexts (data domains)
- [ ] Schema files detected: schema.sql, schema.prisma, *.dbml
- [ ] SQL sources feed into: C4 L2 (database = Container), C4 edges (FK = Relationships), Contracts (table schemas)

## Out of Scope

- Dynamic SQL analysis
- ORM-generated query decompilation
- Cross-database reference resolution
- Database-specific dialect handling beyond standard SQL
- Stored procedure body analysis

## Implementation Notes

- Priority upgraded to P1: SQL analysis is core MVP per exit criteria -- it feeds C4 L2 (database containers) and contract inference (table schemas). Without it, C4 diagrams lack data layer fidelity.
- From section 1.5: SQL uses custom SQL parser (DDL/DML) with 80-90% schema accuracy, 50-60% query accuracy
- SQL is not analyzed for import graphs — it provides data architecture signals instead
- From section 1.5 SQLAnalysis struct: Tables, ForeignKeys, Views, Migrations, StoredProcs, Indexes, DataDomains
- SQL signals feed into: C4 L2 (each database/schema = Container), C4 edges (FKs = Relationships), Contracts (table schemas = observed state), PII detection
- SQL source locations: migrations/, db/migrate/, alembic/versions/, schema.sql, schema.prisma, ORM model files
- PII detection column patterns: email, ssn, phone, address, birth_date, and other personally identifiable field names
- Table clustering algorithm: group tables connected by foreign keys, then identify bounded contexts from cluster boundaries
- Migration analysis: detect schema evolution patterns, breaking changes (column drops, type changes, constraint removals)
