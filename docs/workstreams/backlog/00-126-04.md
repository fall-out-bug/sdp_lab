# 00-126-04: Protocol Consistency Verification and Security Hardening

Feature: F126 (Toolkit MCP -- universal agent interface)

## Goal

Verify that the MCP surface is deterministic and consistent across server instances, and that the server does not widen the local security boundary by accident. End-to-end harness validation is documented as a known gap (see installation.md).

## Beads

- sdplab-g9yf

## Scope Files

- `internal/mcp/server_test.go`
- `internal/mcp/tools_test.go`
- `internal/mcp/resources_test.go`
- `internal/mcp/prompts_test.go`
- `docs/reference/installation.md`

## Acceptance Criteria

- [x] server behavior is consistent for tool calls, resources, and prompts across independent server instances (protocol-level consistency)
- [x] permission boundaries and path handling are explicit and tested
- [x] performance budgets exist for common MCP flows
- [x] security notes document what the MCP layer can and cannot access
- [x] installation.md honestly states: config formats verified; end-to-end harness testing pending
- [ ] end-to-end validation covers at least the supported harness matrix from the design (DEFERRED -- not yet implemented)

## Out of Scope

- new toolkit tools
- org-level deployment
- hosted MCP service

- Design source: `docs/plans/2026-04-13-sdp-mcp-design.md`
- Plan source: `docs/plans/2026-04-13-sdp-mcp-implementation-plan.md`
- The tests renamed from `TestCrossHarness_*` to `TestProtocolConsistency_*` verify protocol surface consistency, not actual harness behavior. End-to-end harness testing requires spawning real harness processes and is tracked as a deferred item.
