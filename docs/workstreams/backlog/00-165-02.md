# 00-165-02: F165 Normalize-Parse-Wrap-Validate Core

Feature: F165 (sdplab-28xb)
Phase: Pilot Evidence & Spec Quality
Status: Backlog

## Goal

Implement the F165 defensive core used by all F165 vectors: Normalize, Parse,
Wrap, and Validate. This is shared inside F165 only; extracting it as a platform
library is out of scope unless a later feature promotes it. The core must use
pre-ingestion trusted-state snapshots, deterministic parser rejection semantics,
closed `blocked_reason` values, and mock-only tool/Beads state.

## Acceptance Criteria

- [ ] Normalize strips/counts zero-width characters, removes HTML comments from model-facing text while recording metadata, classifies suspicious Markdown link targets, and preserves ordinary prose as untrusted narrative.
- [ ] Parse extracts typed fields deterministically and halts malformed required structure as `parse_error`.
- [ ] Wrap exposes typed fields and explicitly delimited untrusted narrative without turning narrative into instructions.
- [ ] Validate compares proposed output/actions with trusted-state snapshots, evidence metadata, scope policy, and tool policy.
- [ ] `blocked_reason` is limited to the closed F165 set from the design doc.
- [ ] Unsafe demo machinery is test-only or build-tagged and cannot call `bd`, `git`, `gh`, network tools, or filesystem writes.
- [ ] Tests prove isolation through fake tool registry assertions and static/runtime checks that the unsafe demo path cannot execute real Beads, Git, network, model, or filesystem-write calls.
- [ ] Targeted unit tests pass without network or live provider credentials.
