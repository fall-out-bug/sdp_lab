# 00-163-01: spec-interrogate critic/judge protocol and dogfood

Feature: F163 (Socratic spec interrogation for sdp-trace pilot)

## Goal

Make `spec-interrogate` precise enough to challenge SpecKit artifacts with clean-context `pi` critics and produce auditable evidence for whether a spec is ready to implement.

## Beads

- sdplab-n7a9.1

## Scope Files

- `prompts/skills/spec-interrogate/SKILL.md`
- `.agents/skills/spec-interrogate.md`
- `.agents/skills/spec-interrogate/SKILL.md`
- `internal/workstream/spec_interrogate_contract_test.go`
- `docs/reviews/2026-04-30-f163-sdp-trace-spec-interrogate.md`
- `docs/reviews/2026-04-30-f163-sdp-trace-spec-interrogate-evidence.json`

## Acceptance Criteria

- [x] The skill defines rubric-scoped Socratic review over the full selected rubric set.
- [x] The critic asks questions only and does not propose fixes or product decisions.
- [x] The judge compares before/after specs plus resolution notes without rewriting the spec.
- [x] Provider rotation covers `zai/glm-5.1`, `kimi-coding/k2p6`, and `minimax/MiniMax-M2.7`.
- [x] The skill records evidence fields for critic provider, judge provider, rubrics, unresolved items, and verdict.
- [x] The protocol is dogfooded on current `sdp-trace` SpecKit specs and the result is evaluated.

## Out of Scope

- Implementing `sdp-trace` itself.
- Turning spec interrogation into a gate. Policy remains owned by `sdp-gate`.
- Giving critic or judge agents file-editing tools.
