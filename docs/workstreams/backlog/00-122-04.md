# 00-122-04: Incremental Refresh, Hooks, and Performance

Feature: F122 (Toolkit Index — persistent codebase memory)

## Goal

Make the index operationally sustainable by refreshing only changed content, exposing update flows, and enforcing performance and safety limits on large repos.

## Beads

- sdplab-760v

## Scope Files

- `internal/index/builder.go`
- `internal/index/store.go`
- `internal/index/search.go`
- `cmd/sdp/cmd_index.go`
- `scripts/hooks/install-git-hooks.sh`

## Acceptance Criteria

- [x] `sdp index refresh` updates only changed files and metadata
- [x] optional watch or hook-based refresh path is explicit, not implicit magic
- [x] large-repo performance budgets are documented and tested
- [x] safety rules skip secrets, credentials, and oversized/generated content on refresh too
- [x] incremental tests prove refresh correctness after file changes

## Out of Scope

- multi-repo indexing
- organization search
- MCP wrapping

## Implementation Notes

- Design source: `docs/plans/2026-04-13-sdp-index-design.md`
- Plan source: `docs/plans/2026-04-13-sdp-index-implementation-plan.md`
- Do not introduce a background daemon as the only supported mode. Manual refresh must remain first-class.
