# 00-134-03: Gate evidence enforcement — no pass without evidence.json

Feature: F134 (sdplab-i01)

## Beads

- sdplab-50p

## Goal

Gate passage blocked unless `evidence.json` exists with required CI control outputs. Currently gates can be passed with manual answer without evidence.

## Scope Files

- `internal/gate/gate.go` — extend: add ResolveWithEvidence method
- `internal/gate/evidence_enforcer.go` — NEW: evidence enforcement logic
- `internal/gate/evidence_enforcer_test.go` — tests

## Design

Extend `internal/gate/gate.go`:
- `ResolveWithEvidence(evidencePath string)` — required for phase gates
- `gate.Resolve()` without evidence path returns error for phase-typed gates
- evidence.json schema per phase:
  - plan -> test coverage + design checklist
  - review -> spec-reviewer output + code-review verdict
  - eval -> go test + go vet + protocol-check + smoke

## Existing Code to Reuse

- `internal/evidence/` — 20 files, attestation + discrepancy + operator_gate + strict mode

## Acceptance Criteria

- [x] `ResolveWithEvidence(answer, answerer, evidencePath)` method added to Gate
- [x] Phase-typed gates require evidence path; returns RequireEvidenceError without it
- [x] `ValidateEvidenceSchema()` enforces per-phase required keys (plan, review, eval)
- [x] `ResolveWithEvidence` delegates to `ValidateEvidenceSchema` for schema enforcement
- [x] Unit tests: gate without evidence blocked, gate with evidence passes, schema validation
- [x] `go vet` clean

## Follow-up Work

- Wire existing beads-backed gate resolvers (gate/beads.go, control/repo_beads.go) through evidence enforcement
- Integration tests with real evidence.json files per phase

## Out of Scope

- Changing evidence format
- Phase commands themselves (F134-01)
