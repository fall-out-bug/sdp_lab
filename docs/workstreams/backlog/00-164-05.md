# 00-164-05: Trusted/untrusted prompt hardening patterns

Feature: F164 (sdplab-9wxx)

## Goal

Harden SDP prompt and skill patterns so untrusted repo, PR, issue, log, handoff, and retrieved context content is rendered as data rather than instructions.

## Acceptance Criteria

- [x] Security/review/build-oriented prompt surfaces document trusted instruction versus untrusted content handling.
- [x] Hardened patterns preserve existing prompt installation unless a decision record accepts a breaking change.
- [x] PromptOps checks include prompt-injection-specific concerns or link to the F164 corpus schema.
- [x] A grep or eval check fails if active prompt surfaces claim prompt-only protection is a security boundary.
- [x] Benign security documentation and tests with injection-like strings remain processable as data through the 00-164-03 mock cases.
- [x] Existing adapter/prompt install validation still passes or the workstream records a decision for any breaking change.

## Out of Scope

- Full runtime sandboxing.
- Refactoring every historical archived prompt.
- Hardening prompts outside the listed active surfaces unless review identifies a blocker.
