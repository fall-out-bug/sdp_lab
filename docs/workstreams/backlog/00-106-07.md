# 00-106-07: Autonomous orchestration loop (`sdp-orchestrate --autonomous`)

Feature: F106 (agentloop Integration)

## Goal

Add `sdp-orchestrate --autonomous` flag — batch-mode pull-FSM loop that calls `--next-action` and `--advance` in a loop with safety limits. Requires `--accept-gates=<list>` allowlist for human gates; exits 3 if gate not in allowlist, exit 4 if same action repeats ≥3 times or `MAX_ITERATIONS=50` exceeded. `--dry-run` required before first real run.

## Beads

- sdplab-lqb

## Scope Files

- `cmd/sdp-orchestrate/main.go` — new `--autonomous` + `--accept-gates` + `--dry-run` + `--max-iterations` flags
- `internal/orchestrate/autonomous.go` — new file with loop driver
- `internal/orchestrate/autonomous_test.go` — tests for loop termination, stuck-detection, allowlist

## Acceptance Criteria

- [ ] `--autonomous --dry-run` prints action sequence without execution
- [ ] `--accept-gates=contract,scope` advances human gates in allowlist; stops on others (exit 3)
- [ ] same action ≥3 times → exit 4 with "loop-stuck" message
- [ ] MAX_ITERATIONS limit respected
- [ ] unit tests cover: happy path, stuck loop, gate allowlist, iteration cap
- [ ] `go vet` + `-race` clean

## Out of Scope

- Real agentloop execution path (F106-01..06 provide that)
- Persistent loop state (each run is fresh)
- Parallel subagent dispatch within loop (belongs to F129-02)

## Implementation Notes

Loop skeleton:

```go
for i := 0; i < maxIter; i++ {
  action := NextAction()
  if action == Done { return nil }
  if action == HumanGate && !inAllowlist(action.Gate) { return ErrHumanRequired }
  if sameAction(history, action, 3) { return ErrLoopStuck }
  Advance(action)
}
```
