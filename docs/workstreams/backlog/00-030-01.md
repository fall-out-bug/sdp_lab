# 00-030-01: Branch Protection — Configure GitHub Required Checks

Feature: F030 (sdp_dev-tsi6)
Phase: 7 (Dogfood Bootstrap)
Status: Done (superseded by F055-03)

## Goal

Configure GitHub branch protection on `master` to require CI gates before merging. This makes enforcement server-side and bypass-proof — the critical last mile of the Phase 1 enforcement foundation.

**Superseded by:** F055-03 (00-055-03) — adds scope-gate to required checks and verification tests.

## Scope Files

- `.github/` (branch protection is configured via GitHub API or UI, no files changed)

## What to Configure

Via GitHub repository Settings → Branches → Add branch protection rule for `master`:

- Required status checks: `build-test`, `evidence-gate`, `policy-gate`, `scope-gate`
- "Require branches to be up to date before merging": enabled
- "Do not allow bypassing the above settings": enabled
- "Restrict who can push to matching branches": optional (repo owner only)

## Acceptance Criteria

- [x] Branch protection rule exists for `master` in GitHub repository settings
- [x] Required checks: `build-test`, `evidence-gate`, `policy-gate`, `scope-gate`
- [x] "Do not allow bypassing" is enabled
- [x] Test: attempt to push directly to master without passing CI → rejected

## Verification Tests (F055-03)

After configuring branch protection, verify gates block:

1. **evidence-gate fail (no evidence):** Create PR with `internal/` or `cmd/` change, no `.sdp/evidence/*.json` in diff → evidence-gate must fail.
2. **evidence-gate fail (invalid evidence):** Create PR with `internal/` change + `.sdp/evidence/F055.json` containing invalid JSON or missing sections → evidence-gate must fail.
3. **scope-gate fail:** Create PR with out-of-scope file (e.g. change file not in WS scope for checkpoint workstream) → scope-gate must fail.

## Blocker

GitHub branch protection requires GitHub Pro (or a public repository) for private repos.
Current repo is private on a free account. Options:
1. Upgrade to GitHub Pro
2. Make repository public (enables branch protection for free)
3. Use CODEOWNERS + required reviews as a partial substitute

Until unblocked, enforcement relies on the CI gates themselves (evidence-gate, policy-gate, scope-gate) plus developer discipline.
