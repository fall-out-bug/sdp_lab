# 00-108-01: `internal/llmclient` — единый LLM-клиент с Chat и SSE Stream

Feature: F108

## Goal

Создать пакет `internal/llmclient` — единую точку HTTP-входа для всех обращений к OpenRouter API. Два метода: `Chat()` для простых запрос-ответ и `Stream()` для SSE-стриминга с аккумуляцией tool_call chunks.

## Beads

- sdplab-4ai

## Scope Files

- `internal/llmclient/llmclient.go` — создать (Client, Chat, типы)
- `internal/llmclient/sse.go` — создать (Stream, SSE-парсер)
- `internal/llmclient/llmclient_test.go` — создать (полное покрытие через httptest)

## Acceptance Criteria

- [ ] `llmclient.New(apiKey, baseURL) *Client` — конструктор без ошибки; пустой ключ не паникует, но `Chat`/`Stream` возвращают ошибку
- [ ] `Chat(ctx, ChatRequest) (*ChatResponse, error)` — POST `/chat/completions`, возвращает Content, FinishReason, токены, стоимость
- [ ] `Stream(ctx, ChatRequest) (<-chan StreamEvent, error)` — SSE, канал закрывается по `data: [DONE]`
- [ ] `StreamEvent.Type` ∈ `{"text_delta", "tool_call", "finish", "error"}`
- [ ] tool_call chunks аккумулируются по `index`; при `finish_reason == "tool_calls"` эмитируется финализированный `ToolCallChunk`
- [ ] Если провайдер вернул пустой tool call ID — генерируется UUID (`github.com/google/uuid`)
- [ ] `go test ./internal/llmclient/... -race` PASS с `httptest.Server`
- [ ] `go vet ./internal/llmclient/...` чистый
- [ ] Ни один другой пакет не делает прямых HTTP-вызовов к `/chat/completions`

## Out of Scope

- Retry-логика (каждый пакет-потребитель делает retry сам)
- Rate limiter
- Кэш

## Implementation Notes

Подробные шаги и код — в `docs/plans/2026-04-11-f108-architecture-normalization-plan.md`, раздел WS-01.

Ключевые типы:
- `ChatRequest{Model, Messages, MaxTokens, Temperature, Tools, Stream}`
- `ChatResponse{Content, FinishReason, InputTokens, OutputTokens, CostUSD}`
- `StreamEvent{Type, Text, Tool *ToolCallChunk, Err}`
- `ToolCallChunk{ID, Name, Arguments}` — ID всегда непустой

SSE-парсер: `bufio.Scanner` по строкам, `data: ` prefix, accumulate by index map.
