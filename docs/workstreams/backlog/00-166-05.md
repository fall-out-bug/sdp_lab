# 00-166-05: OSS gateway substrate fit spike

Feature: F166 (sdplab-mp83)

## Goal

Choose whether F166 should reuse LiteLLM, Instawork `llm-proxy`, a
Grepture-style security proxy, or the existing SDP thin shim as the substrate for
live LLM gateway work.

## Beads

- sdplab-q6yb

## Scope Files

- `docs/plans/2026-05-03-f166-runtime-llm-guard-gateway-design.md`
- `docs/workstreams/INDEX.md`
- `.beads-sdp-mapping.jsonl`

## Acceptance Criteria

- [x] LiteLLM is evaluated against SDP needs: provider coverage, OpenAI-compatible
  API behavior, operational weight, and guard/audit fit.
- [x] Go-native `llm-proxy` is evaluated for provider coverage, test health, and
  extension cost.
- [x] Grepture-style security proxy is evaluated for security fit, license/runtime
  fit, and dependency risk.
- [x] Decision states reuse/fork/build direction for F166.
- [x] Decision preserves F166 guard/audit/rate-limit requirements.

## Decision

Build forward on the SDP thin shim. Do not adopt LiteLLM, Instawork
`llm-proxy`, or Grepture as an F166 runtime dependency.

## Out of Scope

- Replacing `internal/llmguard`.
- Implementing streaming.
- Adopting a third-party gateway control plane.
