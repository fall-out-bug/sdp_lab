# 00-131-02: Skill augmenter — inject stack-specific sections into existing skills

Feature: F131 (sdplab-ait)

## Goal

Build a CLI tool (`sdp skills augment`) that reads a stack config (JSON: language, test framework, linter, etc.) and injects stack-specific sections into existing skill files within `<!-- STACK_SPECIFIC -->` marker boundaries. Idempotent: re-running overwrites only marker-bounded blocks.

## Beads

- sdplab-ho8 (F131-02)

## Scope Files

- `cmd/sdp/skills_augment.go` — new. `sdp skills augment` subcommand.
- `internal/skills/augment.go` — new. Core augmenter logic: parse markers, render templates, write.
- `internal/skills/augment_test.go` — tests.
- `configs/stack-configs/` — new dir. Example stack configs (go-default.json, python-default.json, typescript-default.json).
- `internal/skills/testdata/` — fixture skill files with markers for testing.

## Acceptance Criteria

- [ ] `sdp skills augment --stack configs/stack-configs/go-default.json` updates marker blocks in `.agents/skills/build.md`
- [ ] Idempotent: second run produces byte-identical output
- [ ] Dry-run mode: `--dry-run` prints diff without writing
- [ ] Validation: `--validate` checks all marker blocks are well-formed (balanced begin/end)
- [ ] Stack config schema documented in `docs/reference/skill-marker-convention.md`
- [ ] Unit tests: marker parsing, template rendering, idempotency, validation

## Out of Scope

- Scout/report integration (was F130-02 dependency — simplified to manual config)
- Bootstrap wiring (→ 00-131-03)
- Creating new skills from scratch (augmenter only modifies existing ones)
