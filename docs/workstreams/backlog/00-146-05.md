# 00-146-05: Monolithic ws-verdict baseline for A/B benchmark

Feature: F146 (Inference Decomposition Framework)

Design reference: [2026-04-26-f146-inference-decomposition-design.md §3 F146-05](../../plans/2026-04-26-f146-inference-decomposition-design.md)

## Goal

Ship the single-prompt monolithic ws-verdict adapter — the honest A/B baseline against the 3-stage decomposed pipeline. Wraps the existing F144 confidence full-set (self-check + N=3 + constraint), uses Sonnet (consistent with classify-stage of decomposed). Exposes a `Result[FinalVerdict]`-shaped output (with one synthetic stage `monolithic`) so the bench harness consumes both paths uniformly. Runs in parallel with 00-146-04.

## Beads

- sdplab-tj6g (historical leaf issue)

## Scope Files

- `internal/inference/decompose/adapters/wsverdict/monolithic.go` — new. `NewWSVerdictMonolithic(client llmclient.Client) MonolithicRunner`. Returns `Run(ctx, Diff) (decompose.Result[FinalVerdict], error)`.
- `internal/inference/decompose/adapters/wsverdict/monolithic_prompt.go` — new. Single combined prompt = concat of extract + classify + aggregate instructions, expecting full `FinalVerdict` JSON in one response.
- `internal/inference/decompose/adapters/wsverdict/monolithic_test.go` — new. 3 fixture smoke tests (mock LLM); verifies same `FinalVerdict` shape.

## Acceptance Criteria

- [ ] `NewWSVerdictMonolithic(client)` returns runner whose `Run(ctx, Diff)` yields `decompose.Result[FinalVerdict]`.
- [ ] Prompt is single-shot: one LLM call returns full `FinalVerdict` JSON (verdict + blocking_gates + score + summary).
- [ ] Confidence wrap: full F144 set (self-check + N=3 + constraint) — same profile as classify-stage of decomposed for fair A/B.
- [ ] Model: `Sonnet` (matches decomposed classify-stage).
- [ ] Output `Result.StageResults` length 1, single `StageResult.Name == "monolithic"`. Trace populated with latency / tokens / cost.
- [ ] Output `FinalVerdict` semantically equivalent shape to decomposed adapter output (same fields, types, value domains) — bench harness will diff them.
- [ ] 3 fixture smoke tests with mock LLM responses pass: clean → passed, mixed → partial, fail → failed.
- [ ] Coverage of monolithic.go ≥ 85 %.
- [ ] `go build ./...` and `go vet ./...` clean.

## Out of Scope

- Bench harness invocation (→ 00-146-06).
- Decomposed adapter (→ 00-146-04, runs in parallel).
- Monolithic prompt optimization — first version is straight concat of decomposed-stage instructions, no tuning. Tuning is bench-driven follow-up if accuracy regresses.
- Honest-baseline argumentation document (rationale lives in the design doc §3 F146-05).
