# 00-166-07: Codex and Pi gateway integration smoke

Feature: F166 (sdplab-mp83)

## Goal

Prove that `sdp-llm-gateway` can become the single local guard boundary for
Codex and Pi before provider egress. The gateway must speak the protocol shapes
that those harnesses actually send, while preserving the F166 invariant:
scan/classify/redact/block before any upstream provider call and write safe audit
evidence for every decision.

## Acceptance Criteria

- [x] Design states Codex compatibility requires an OpenAI Responses API surface
  at `/v1/responses` with SSE events and a terminal `response.completed` event.
- [x] Design states Pi compatibility requires OpenAI Chat Completions streaming
  at `/v1/chat/completions` with `stream: true`.
- [x] Specification requires the gateway guard path to run before upstream egress
  for both harness surfaces.
- [x] Specification requires blocked input to return harness-shaped safe
  responses without calling the upstream provider.
- [x] Specification requires streaming output not to be released raw before
  output guard policy has a chance to scan or buffer it.
- [x] Specification requires audit events to include harness name, model,
  endpoint surface, guard verdict, classifier completeness, and upstream-called
  yes/no without raw secrets.
- [x] Fake-endpoint smoke evidence records Codex and Pi request paths, headers,
  streaming expectations, and failure mode for missing SSE completion.
- [x] Implementation plan includes deterministic tests for Codex blocked/allowed
  Responses calls and Pi blocked/allowed streaming Chat Completions calls.

## Testable Assertions

- Codex blocked: fake upstream receives no request; client stream terminates with
  `response.completed`; audit has `upstream_called: false`.
- Codex clean: fake upstream receives one guarded request; client stream
  terminates with `response.completed`; audit has `upstream_called: true`.
- Pi blocked: fake upstream receives no request; response shape matches the
  request `stream` flag; audit has `upstream_called: false`.
- Pi clean: fake upstream receives one guarded streaming request; client receives
  a valid Chat Completions stream; audit has `upstream_called: true`.
- Audit: every serialized event includes `harness`, `endpoint_surface`,
  `verdict_state`, `stream_requested`, `stream_returned`, and no raw prompt or
  raw secret text.
