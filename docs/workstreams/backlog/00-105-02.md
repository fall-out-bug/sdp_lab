## Implementation Notes

- From section 1.2: CodebaseProfile is an "information bottleneck" — compresses structural signals with tiered depth
- Tier 1 (always available): containers, languages, external deps, spec inventory — sufficient for L1/L2 C4 and style hypothesis
- Tier 2 (on-demand per container): import graph, component list, API surfaces, test coverage — for L3 C4 and conformance
- Tier 3 (on-demand per component): actual code for specific files — for L4, pattern detection, contract inference
- Context assembly is question-driven: design review uses Tier 1 + selective Tier 2; impact analysis starts from changed files (Tier 3)
- From section 1.3: 8 reliably detectable styles only. HumanInputNeeded field lists styles that cannot be determined from code alone
- From section 3.1: Contract lifecycle is 3 states (observed -> proposed -> reference), each with different confidence gates
- New schemas to register: architecture-model, architecture-analysis, contract-catalog, architecture-conformance, architecture-findings
