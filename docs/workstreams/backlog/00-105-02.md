# 00-105-02: Core Types + Profile Assembly

Feature: F105 (AI Architect)

## Goal

Define the canonical type system (DependencyInfo split, deterministic IDs, C4 types) and implement the profile assembly pipeline that merges signals from all extractors with explicit precedence.

**Source spec:** `docs/plans/2026-04-10-ai-architect-impl-datamodel.md` (7 rounds of council review, unanimously approved)

## Acceptance Criteria

### Canonical Types (Spec Sections 1-2)
- [ ] DependencyInfo split into 4 disjoint types: ManifestDependency, DependencyCorrelation, StructuralEdge, LLMEnrichment
- [ ] EdgeKind enum: import, call, implements, persists_to, exposes, contains
- [ ] Module, ModuleDependency, Component, APISurface, ModuleBoundary, LayerAssignment types defined
- [ ] Component type aliased as C4Component: `type C4Component = Component`
- [ ] LLMEnrichment stored in separate `map[string]LLMEnrichment`, never as struct field on Module/Component/Edge
- [ ] DepType enum: import, require, dynamic
- [ ] ComponentType enum: service, library, application

### Deterministic IDs (Spec Section 3)
- [ ] ID format: `<language>\x00<package-path>\x00<module-name>` (null byte separator)
- [ ] SplitID: splits on `\x00`, decodes `%00` back to `\x00` within segments, validates 3 segments
- [ ] JoinID: encodes `\x00` in segments as `%00`, joins with `\x00`, rejects empty segments
- [ ] NormalizeID: `JoinID(SplitID(id)) == id` — canonical form for all comparisons
- [ ] Idempotency invariant: `JoinID(SplitID(id)) == id` for well-formed IDs
- [ ] Hash disambiguation: suffix in 3rd segment (`name~abc12345`), NOT 4th segment
- [ ] External deps: `ext\x00<ecosystem>\x00<name>`
- [ ] Containers: `container\x00<name>`
- [ ] No encoding/decoding of `%00` outside JoinID/SplitID

### Profile Assembly (Spec Section 4)
- [ ] ProfileFragment emitted by each extractor
- [ ] Per-field merge rules: modules/dependencies by ID union, edges by (source,target,kind,protocol), boundaries by name union
- [ ] Extractor precedence (HIGHER number wins): FileTree(1) < DepManifest(2) < SpecInventory(3) < Infra(4) < Language(Go=0,Python=1,Java=2,TS=3,SQL=4 -> base 5+offset) < ImportGraph(6)
- [ ] Once higher-precedence extractor populates a key, no lower may overwrite (race-safe)
- [ ] CodebaseProfile top-level output with Enrichment as `map[string]LLMEnrichment`

### Serialization (Spec Section 5)
- [ ] `omitempty` on all optional fields
- [ ] No null values — omit key entirely
- [ ] Arrays never null — empty `[]`
- [ ] Confidence always present [0.0, 1.0]
- [ ] Timestamps in RFC3339
- [ ] IDs are strings, never integers
- [ ] Output: `{target-repo}/.sdp/architecture/codebase-profile.json`

## Implementation Notes

- The null byte ID scheme replaces the previous `::` delimiter (council Round 5 found C++/Rust/Java collisions)
- LLMEnrichment is NEVER a struct field — always in a separate map keyed by node/edge ID
- The DependencyInfo split was mandated by council to prevent conflation of manifest entries, graph topology, and LLM annotations
- Existing `model.go` already has some of these types — update, don't replace
