# 00-105-12: CLI Integration + Pipeline Orchestration

Feature: F105 (AI Architect)

## Goal

Wire the `sdp architect analyze` CLI command with full pipeline orchestration of all extractors and LLM interpretation, and produce output artifacts. Evaluation harness and golden repos are handled by WS13.

## Beads

- sdplab-tx1h: historical shipped feature anchor for F105 (PR #86)

## Scope Files

- `cmd/sdp/architect.go` — `sdp architect` CLI command registration
- `cmd/sdp/architect_analyze.go` — `sdp architect analyze <path>` full integration
- `cmd/sdp/architect_analyze_test.go`
- `internal/architect/pipeline.go` — end-to-end pipeline orchestrator
- `internal/architect/pipeline_test.go`
- `internal/architect/progress.go` — progress reporting (spinner, stage indicators)
- `internal/architect/output.go` — output artifact generation (report, C4, profile)

## Acceptance Criteria

- [ ] `sdp architect analyze <path>` runs full pipeline: extract -> assemble -> filter -> LLM interpret -> generate C4 -> output report
- [ ] Progress reporting shows current stage (extracting, analyzing, generating) with estimated time remaining
- [ ] Output artifacts placed in `{target-repo}/.sdp/architecture/`: report.json, c4/*.mmd, profile.json
- [ ] `--format` flag supports: json, text (human-readable summary), mermaid (diagrams only)
- [ ] `--tier` flag controls depth: 1 (system overview), 2 (container detail), 3 (component source)
- [ ] `--allow-external-llm` flag required for cloud LLM usage
- [ ] Output schema validates against architecture-analysis.schema.json
- [ ] Pipeline stages independently runnable for debugging and incremental analysis

## Out of Scope

- Evaluation harness framework (WS13)
- Golden repo test suite (WS13)
- Metrics collection framework (WS13)
- `sdp architect conform` command (Phase C)
- `sdp architect greenfield` command (Phase C)
- `sdp architect contracts` command (Phase B)
- `sdp architect export --format backstage` (Phase B)
- CI/CD integration (govern mode, Phase C)
- Backstage catalog-info.yaml export

## Implementation Notes

- From section 7.2: invocation triggers — `@architect analyze <path>` runs full analysis in probe mode
- Probe mode: one-shot analysis, produces report + hypothesis + C4 draft, no persistent state (section 6)
- Pipeline stages: extract -> assemble -> security filter -> LLM interpret -> C4 generate -> output
- Uses evaluation harness from WS13 for exit criteria validation in CI
- Output schema should validate against architecture-analysis.schema.json
- Pipeline stages should be independently runnable for debugging and incremental analysis
