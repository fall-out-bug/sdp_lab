# 00-158-01: Decision artifact — Go import-path contamination (options A/B/C)

Feature: F158 (sdplab-guga)
Parent bead: sdplab-guga.1

## Goal

Make an explicit, documented decision on how to handle Go import-path namespace for IIP tools so F156 and F157 can begin. The risk: `github.com/<sdp-lab-org>/sdp_lab/arch-snap` permanently associates the tool with SDP in every Go import statement across the ecosystem.

## Beads

- sdplab-guga.1

## Options to Evaluate

| Option | Description |
|--------|-------------|
| A | Neutral GitHub org from inception — incubate at `incubator-org/arch-snap` while developed by SDP team |
| B | Accept contamination during incubation; change import path mechanically at extraction (`git filter-repo`) |
| C | Hybrid — monorepo sub-path during very early phase (`sdp_lab/experiments/arch-snap`); move to neutral org at v0.1 |

## Scope Files

- `docs/strategy/iip-import-path-decision.md` — decision artifact (ADR format)

## Acceptance Criteria

- [ ] Decision document covers each option across:
  - Non-SDP adopter perception (does the path discourage adoption?)
  - Developer-experience cost (complexity of setup, `replace` directives risk)
  - Infrastructure cost (org management, CI permissions, secrets)
  - Governance complexity (who owns the neutral org?)
  - Extraction mechanics (how hard is the final split?)
- [ ] Recommendation stated with rationale
- [ ] If Option A chosen: neutral org name and governance plan documented
- [ ] If Option B chosen: extraction playbook (`git filter-repo` steps) documented
- [ ] If Option C chosen: phase-transition trigger and timeline documented
- [ ] ADR format: Context / Decision / Consequences / Alternatives
- [ ] F156 and F157 can begin once this artifact exists and chosen option is applied

## Out of Scope

- Creating the neutral org (if A/C chosen) — that is a first step of F156/F157
- Implementation of any IIP code
