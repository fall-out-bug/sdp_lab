# 00-106-03: ServeBridge — wiring Harness в DispatchAndRun

Feature: F106 (agentloop Integration)

## Goal

Подключить `agentloop.Harness` в `ServeBridge.DispatchAndRun()` как основной execution path. После этого SDP реально управляет tool calls агента, а не только парсит его stdout.

## Beads

- sdplab-jhzy

- `internal/executor/bridge_serve_test.go` — добавить тесты
- `internal/agentloop/harness.go` — добавить `IsAwaitingHuman() bool` accessor (минимальное изменение)
- `internal/agentloop/router.go` — читать (PhaseRouter, DefaultPhaseMap — не менять)

## Acceptance Criteria

- [ ] `ServeBridge` получает три новых private поля: `harnessRouter *agentloop.PhaseRouter`, `harnessGate *agentloop.GateEngine`, `harnessData string`
- [ ] `NewServeBridge()` инициализирует harness поля: `NewLiveGateway` + `BuildLiveTools` + `NewToolRegistry` + `NewPhaseRouter` + `NewGateEngine`; `harnessData = projectRoot+"/.sdp/sessions"`
- [ ] `DispatchAndRun()` имеет два пути: если `harnessRouter != nil` → `runWithHarness()`; иначе → существующий OmO path (nil-check fallback)
- [ ] `runWithHarness()` создаёт SQLite store в `harnessData/<cardID>.db`, вызывает `RestoreHarness`, затем `h.RunPhase(ctx, governedPrompt, "")`
- [ ] При `RunPhase` success → `ExecutorResultPacket{Status: "completed", CardID: cardID}`
- [ ] При `RunPhase` error → `ExecutorResultPacket{Status: "failed", Error: err.Error()}`
- [ ] Добавить публичный accessor в `harness.go`: `func (h *Harness) IsAwaitingHuman() bool` — возвращает `true` если внутреннее состояние `hStateAwaitingHuman`; НЕ экспортировать `harnessState` тип
- [ ] При `h.IsAwaitingHuman()` == `true` после RunPhase → `ExecutorResultPacket{Status: "gate-pending", CardID: cardID}`
- [ ] `go test ./internal/executor/ -run TestServeBridgeHarness -race` PASS (использует `StubGateway` + in-memory store)
- [ ] Все существующие тесты `./internal/executor/...` остаются PASS
- [ ] `go build ./...` без ошибок

## Implementation Notes

```go
func (b *ServeBridge) runWithHarness(ctx context.Context, card *control.FeatureCard, 
    packet *control.ExecutionPacket, prompt string) (*control.ExecutorResultPacket, error) {
    
    if err := os.MkdirAll(b.harnessData, 0755); err != nil {
        return nil, fmt.Errorf("create sessions dir: %w", err)
    }
    dbPath := filepath.Join(b.harnessData, card.ID+".db")
    
    store, err := agentloop.NewSQLiteStore(dbPath)
    if err != nil {
        return nil, fmt.Errorf("open session store: %w", err)
    }
    
    h, err := agentloop.RestoreHarness(card.ID, "", store, b.harnessRouter, b.harnessGate, nil)
    if errors.Is(err, agentloop.ErrHarnessTerminated) {
        // Старая сессия terminated — начать заново (см. spec §11)
        if removeErr := os.Remove(dbPath); removeErr != nil && !os.IsNotExist(removeErr) {
            return nil, fmt.Errorf("remove terminated session: %w", removeErr)
        }
        store, err = agentloop.NewSQLiteStore(dbPath)
        if err != nil {
            return nil, fmt.Errorf("recreate session store: %w", err)
        }
        h, err = agentloop.RestoreHarness(card.ID, "", store, b.harnessRouter, b.harnessGate, nil)
    }
    if err != nil {
        return nil, fmt.Errorf("restore harness: %w", err)
    }
    
    if err := h.RunPhase(ctx, prompt, ""); err != nil {
        return &control.ExecutorResultPacket{Status: "failed", Error: err.Error()}, nil
    }
    return &control.ExecutorResultPacket{Status: "completed", CardID: card.ID}, nil
}
```

**Тест strategy**: создать `ServeBridge` с `harnessRouter` из `StubGateway` + in-memory `SessionStore`. `StubGateway.AddResponse(model, []Event{...completion_signal...})`. Вызвать `runWithHarness`. Проверить что session db создан и `ExecutorResultPacket.Status == "completed"`.

Доступ к `h.State()`: в `harness.go` нет публичного метода. Для MVP: проверить через попытку повторного `RunPhase` (должна вернуть `"harness busy: state=2"` если AwaitingHuman). Или добавить `State() harnessState` accessor — минимальный публичный метод.
