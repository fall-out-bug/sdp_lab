# 00-135-01: Vibecode-to-SDP promotion bridge

Feature: F135-05 (Vibecode-to-SDP bridge)

## Goal

Bridge vibecode mode (`sdp build`) to strict Phase FSM (`sdp phase`), enabling opt-in escalation without redoing work. Two paths: mid-run promotion and retroactive wrapping.

## Beads

- sdplab-nj4: F135-05 Vibecode-to-SDP bridge

## Scope Files

- `internal/promote/promote.go` (new) — Bridge logic: BuildEvidence → Delta artifacts + Gates
- `internal/promote/promote_test.go` (new) — Unit tests
- `cmd/sdp/cmd_phase_from_run.go` (new) — `sdp phase from-run <run_id>` subcommand
- `cmd/sdp/cmd_phase_from_run_test.go` (new) — CLI tests
- `internal/build/pipeline.go` (modify) — Wire `--promote-to-strict` mid-run switch
- `cmd/sdp/cmd_build.go` (modify) — Add `--promote-to-strict` flag
- `cmd/sdp/cmd_phase.go` (modify) — Add `from-run` subcommand dispatch

## Acceptance Criteria

- [ ] AC1: `sdp build --promote-to-strict "<idea>"` runs vibecode pipeline then switches to strict Phase FSM mid-run (plan → review → eval gates created and awaiting approval)
- [ ] AC2: `sdp phase from-run <run_id>` reads `.sdp/evidence/<run_id>/evidence.json` and produces valid `plan.delta.md`, `review.delta.md`, `eval.delta.md` with `source: vibecode-promoted`
- [ ] AC3: Retroactively created gates open with pre-populated evidence from vibecode run (build_ok, tests_ok, classification, dispatch decision)
- [ ] AC4: Vibecode `BuildEvidence` schema is superset-compatible with F134-03 `evidence.json` — no rewrite needed, promotion reads evidence as-is
- [ ] AC5: No work duplication — promoted run reuses existing evidence artifacts, only generates delta gate wrappers
