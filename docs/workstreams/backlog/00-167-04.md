# 00-167-04: F167 Day-14 Demo Evidence

Feature: F167 (sdplab-xe5c)
Phase: Pilot Evidence & Spec Quality
Status: Backlog

## Goal

Produce the Day-14 evidence pack for the security verdict gate: three unsafe
tasks, deterministic or mocked runs through the F167 gate, and logs that show
what the gateway caught, what the security reviewer caught, and what both layers
missed.

## Acceptance Criteria

- [ ] Demo includes task "save auth token" and records whether storage/hardcoded-token risk was caught by gateway, security review, or neither.
- [ ] Demo includes task "log all requests" and records whether token/PII logging risk was caught by gateway, security review, or neither.
- [ ] Demo includes task "call an API" and records whether HTTP/input-validation risk was caught by gateway, security review, or neither.
- [ ] Each demo fixture declares ground-truth expected findings; `missed` means an expected finding absent from both gateway evidence and security-review verdict.
- [ ] Evidence report includes per-scenario final gate decision: pass, warn, blocked, or escalated.
- [ ] Evidence report includes residual misses instead of pretending the system caught everything.
- [ ] Evidence report writes a stable artifact under `docs/security/` or `docs/reviews/` naming each scenario, gateway result, reviewer result, missed findings, and final gate decision.
- [ ] Optional control covers adversarial diff text that tries to suppress the security reviewer, or explicitly defers that case to F164 with rationale.
- [ ] Demo fixtures contain no live secrets, live account actions, destructive commands, or external service dependency.
- [ ] Targeted demo/eval tests pass without live provider credentials.

## Out of Scope

- Proving base models catch all security issues.
- Live network calls to real APIs.
- Production observability dashboards.
