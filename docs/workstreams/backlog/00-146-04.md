# 00-146-04: ws-verdict 3-stage pipeline adapter

Feature: F146 (Inference Decomposition Framework)

Design reference: [2026-04-26-f146-inference-decomposition-design.md §3 F146-04](../../plans/2026-04-26-f146-inference-decomposition-design.md)

## Goal

Ship the first F146 adapter — ws-verdict as a 3-stage decomposed pipeline (extract → classify → aggregate) with per-stage model selection (Haiku → Sonnet → Haiku), per-stage confidence profile, and per-stage stitcher (JSON → Enum → TOON). Provide opt-in flag `--decompose` on `sdp-ws-verdict-validate` so default behavior remains unchanged.

## Acceptance Criteria

- [ ] `NewWSVerdictPipeline` returns a `Pipeline[FinalVerdict]` with exactly 3 stages: `extract`, `classify`, `aggregate`.
- [ ] **extract** stage — model `Haiku`, confidence profile `constraint-only` (lite), stitcher `JSON` (`ws-verdict-extracted.json`), failure policy `RetryOnce`. Output: `ExtractedFacts {files_changed, tests_added, coverage_delta, lint_status, build_status}`.
- [ ] **classify** stage — model `Sonnet`, confidence profile `self-check + N=3 sample`, stitcher `Enum` per gate (4 gates: build, test, lint, coverage; each ∈ `pass|warn|fail`), failure policy `Abort`. Output: `GateMatrix`.
- [ ] **aggregate** stage — model `Haiku`, confidence profile `constraint-only` (lite), stitcher `TOON`, failure policy `Fallback` (FallbackOut: safe-fail verdict). Output: `FinalVerdict {verdict ∈ {passed, partial, failed}, blocking_gates[], score, summary}`.
- [ ] End-to-end test on 3 fixtures (mock LLM): clean-pass → `passed`; mixed → `partial` with blocking gates; fail → `failed`.
- [ ] Stage 2 simulated failure (mock returns malformed enum) → pipeline aborts, `Result.Status == FAIL`, `StageResult.Trace.StitcherErr` populated.
- [ ] Per-stage tokens/latency captured in evidence; aggregate `Result.Trace` is sum of `StageResult.Trace.LatencyMs / TokensIn / TokensOut`.
- [ ] `cmd/sdp-ws-verdict-validate --decompose <input>` runs the pipeline; without flag, default behavior is byte-for-byte unchanged (regression test).
- [ ] Schema files validate against existing JSON Schema validator (sanity test in schema package).
- [ ] Coverage of `adapters/wsverdict/` ≥ 80 % (lower bar than core lib due to LLM-bound paths).
- [ ] `go build ./...` and `go vet ./...` clean.
