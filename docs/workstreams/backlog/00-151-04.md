# 00-151-04: Override Protocol

Feature: F151 (sdplab-hfk0)
Parent bead: sdplab-hfk0.4

## Goal

Override protocol design: who can override, comment-trigger format, required fields (owner+reason+timestamp+evidence snapshot), audit log entry. GitHub PR comment example.

## Beads

- sdplab-hfk0.4

## Scope Files

- `docs/design/sdp-pr-gate/override-protocol-v1.md` — protocol design doc

## Acceptance Criteria

- [ ] Override roles defined: decision_owner, reviewer, admin (from manifesto)
- [ ] Comment-trigger format specified (e.g. `@changepassport override --reason="..."`)
- [ ] Required override fields: owner, reason, timestamp, evidence snapshot reference
- [ ] Override produces visible marker in passport
- [ ] Override produces append-only audit entry
- [ ] Protocol covers: who can override what decisions, revocation, conflict resolution
- [ ] At least 2 GitHub PR comment examples with parsing rules
- [ ] Security considerations: impersonation prevention, comment verification
- [ ] Design doc explains: comment parsing grammar, error handling for malformed triggers

## Out of Scope

- Implementation code
- GitHub App webhook handling (00-151-05)
- Non-GitHub override triggers

- ChangePassport manifesto v2 §"Decision And Override" (roles, comment example)
- ChangePassport manifesto v2 §"Evidence Integrity" (append-only audit)
