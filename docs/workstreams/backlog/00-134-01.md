# 00-134-01: Phase commands — sdp plan / sdp review / sdp eval CLI wiring

Feature: F134 (sdplab-i01)
Beads: sdplab-kkk

## Goal

Wire `sdp plan`, `sdp review`, `sdp eval` as first-class CLI entry points over existing `internal/discovery/` and `internal/gate/`.

## Scope Files

- `cmd/sdp/cmd_plan.go` — NEW: Plan phase command
- `cmd/sdp/cmd_review.go` — NEW: Review phase command
- `cmd/sdp/cmd_eval.go` — NEW: Eval phase command
- `cmd/sdp/main.go` — wire new commands

## Existing Code to Reuse

- `internal/discovery/` — 10 files, full phase FSM
- `internal/gate/gate.go` — Gate struct with Question/Options/Answer/Resolved
- `internal/gate/beads.go` — beads integration
- `internal/evidence/` — 20 files, attestation + trace_validator

## Acceptance Criteria

- [ ] `sdp plan` loads current WS/feature context, emits Plan delta, opens gate, blocks until resolved
- [ ] `sdp review` verifies implementation against plan, checks evidence, emits Review delta, opens gate
- [ ] `sdp eval` runs quality gates, attestation checks, emits Eval delta, opens gate
- [ ] All three follow same pattern: load context -> emit delta -> open gate -> wait resolve -> emit trace record
- [ ] Unit tests for each command
- [ ] `go vet` clean

## Out of Scope

- Delta artifact format (F134-02)
- Evidence enforcement (F134-03)
- Skill integration (F134-06)
