# 00-149-01: Product docs rebaseline for SDP onboarding

Feature: F149 (Product Documentation Rebaseline)

Design reference: [product-surface.md](../../reference/product-surface.md)

## Goal

Make the public documentation honest and immediately useful for CTOs, architects, and developers evaluating SDP as a structured AI PDLC/SDLC harness layer. A new reader should understand how to install SDP, what to configure, which capabilities are ready, which parts are operator tooling, and which lanes are experiments.

- sdplab-ndsc (bug discovered during F149: installer missing sqlite_fts5 build tag)
- sdplab-43i6 (follow-up: stale phantom CLI reference docs)
- sdplab-t5k3 (follow-up: strict doc-sync warning backlog)

## Scope Files

- `README.md` — clarify public repo role, install path, product positioning, current capabilities, and limitations.
- `docs/QUICKSTART.md` — replace stale/phantom command flow with real commands from `cmd/sdp/main.go`.
- `docs/runbooks/onboarding-downstream-repo.md` — align downstream setup with actual installer and verification commands.
- `docs/reference/product-surface.md` — new canonical user-facing product map.
- `docs/reference/project-map.md` — align repo role and read-order with current public `sdp_lab` / distilled `sdp` boundary.
- `docs/reference/canonical-happy-path.md` — show separate happy paths instead of one overloaded flow.
- `docs/architecture/REPO-BOUNDARY.md` and `docs/MULTI-REPO-WORKFLOW.md` — update repo boundary language.
- `AGENTS.md` — update only shared repo-role wording needed for consistency.
- `docs/workstreams/INDEX.md`, `docs/roadmap/ROADMAP.md`, `.beads-sdp-mapping.jsonl` — register the workstream.

## Acceptance Criteria

- [ ] Canonical entrypoint explains what SDP is, who it is for, and what repo to use.
- [ ] Install/setup path lists real prerequisites, commands, harness support, and verification commands.
- [ ] Feature map separates ready user-facing capabilities, operator/internal tooling, and experimental/research lanes.
- [ ] Docs describe multiple happy paths rather than one overloaded path.
- [ ] Demo/readme narrative is description-only but honest about current limitations.
- [ ] Stale or contradictory doc references discovered in the audit are fixed or filed as follow-up beads.

## Out of Scope

- Building a new runnable demo.
- Rewriting every historical plan, archive, or obsolete reference doc.
- Publishing to the distilled `sdp` repo before this branch is merged.
- Productizing ChangePassport in this workstream.
