# Getting Started with SDP Trust Layer

Add SDP (Structured Development Protocol) to your AI coding project in 10 minutes.

SDP answers: "Did the AI agent actually plan this, stay in scope, run tests, and get reviewed — or did it just wing it?"

---

## What SDP Does

SDP sits between your AI coding agent (Cursor, Claude Code, opencode) and your `git` merge flow:

```
Agent writes code
      ↓
CI auto-generates evidence attestation (what actually happened)
      ↓
CI gates validate: scope, tests, policies
      ↓
Attestation signed with Sigstore (keyless)
      ↓
PR comment shows summary
      ↓
Human reviews and merges
```

No agent action required. Evidence is generated from CI observation (Tekton Chains model).

---

## Prerequisites

- GitHub Actions (or any CI with `git` available)
- Go 1.21+ (for sdp-evidence CLI)
- [Optional] OPA CLI for policy enforcement
- [Optional] cosign for Sigstore signing

## Step 1: Install sdp-evidence

```bash
# macOS/Linux: download from GitHub Releases
curl -sLO https://github.com/fall-out-bug/sdp_dev/releases/latest/download/sdp-evidence_Darwin_arm64.tar.gz
tar xf sdp-evidence_Darwin_arm64.tar.gz
sudo mv sdp-evidence /usr/local/bin/
```

Or build from source:

```bash
git clone https://github.com/fall-out-bug/sdp_dev
cd sdp_dev
go build ./cmd/sdp-evidence
```

## Step 2: Add CI Jobs

Copy these jobs into your `.github/workflows/ci.yml`:

### Auto-Attestation (generates evidence automatically)

```yaml
auto-attestation:
  runs-on: ubuntu-latest
  if: github.event_name == 'pull_request'
  permissions:
    contents: read
    id-token: write
    pull-requests: write
  steps:
    - uses: actions/checkout@v4
      with:
        fetch-depth: 0

    - uses: actions/setup-go@v5
      with:
        go-version: '1.26'

    - name: Generate + sign attestation
      env:
        PR_NUMBER: ${{ github.event.pull_request.number }}
        PR_URL: ${{ github.event.pull_request.html_url }}
        BASE_REF: ${{ github.base_ref }}
      run: |
        mkdir -p .sdp/attestations
        go run github.com/fall-out-bug/sdp_dev/internal/evidence/cmd/auto-attest@latest \
          --base-branch "$BASE_REF" \
          --pr-number "$PR_NUMBER" \
          --pr-url "$PR_URL" \
          --output .sdp/attestations/ci-auto.json \
          --report .sdp/attestations/ci-auto-report.json || true
```

### Evidence Gate (validates evidence on PRs that touch feature code)

```yaml
evidence-gate:
  runs-on: ubuntu-latest
  if: github.event_name == 'pull_request'
  steps:
    - uses: actions/checkout@v4
      with:
        fetch-depth: 0

    - uses: actions/setup-go@v5
      with:
        go-version: '1.26'

    - name: Validate evidence
      run: |
        EVIDENCE_FILES=$(git diff --name-only origin/${{ github.base_ref }}...HEAD | grep '^\\.sdp/evidence/.*\\.json$' || true)
        if [ -z "$EVIDENCE_FILES" ]; then exit 0; fi
        for f in $EVIDENCE_FILES; do
          sdp-evidence validate --require-pr-url=false "$f"
        done
```

## Step 3: Add OPA Policies (Optional)

Create `.sdp/policies/` and add Rego files:

```bash
mkdir -p .sdp/policies
```

**`.sdp/policies/enforcement_level.rego`** — Start advisory, flip to blocking when ready:

```rego
package sdp.policies
default enforcement_level = "advisory"  # change to "blocking" when ready
```

**`.sdp/policies/evidence_required.rego`** — Require evidence when workstream files change:

```rego
package sdp.policies
deny[msg] {
  input.has_workstream_changes
  input.evidence_files_count == 0
  msg := "PR changes workstream files but has no evidence attestation"
}
```

Add to `.gitignore`:
```
# Track SDP policies (don't ignore them)
!.sdp/policies/
```

## Step 4: Use sdp-evidence CLI

```bash
# Validate an attestation
sdp-evidence validate .sdp/evidence/F028.json

# Human-readable summary
sdp-evidence inspect .sdp/evidence/F028.json

# Check what evidence exists
ls .sdp/evidence/
```

## Light Mode vs Full Mode

| | Light Mode | Full Mode |
|---|---|---|
| **Who creates evidence?** | CI auto-observes | Agent + CI |
| **Workstream files?** | Not required | Auto-generated by `@feature` |
| **Enforcement?** | CI gates (advisory) | CI gates + OPA + FSM conformance |
| **For whom?** | Human + coding agent | Autonomous `@oneshot` |

Start with **Light Mode** — just add the CI jobs and let evidence generate automatically.

## What the Evidence Contains

Each attestation is an [in-toto](https://github.com/in-toto/attestation) statement with predicate type `https://sdp.dev/attestation/coding-workflow/v1`:

```json
{
  "_type": "https://in-toto.io/Statement/v0.1",
  "predicateType": "https://sdp.dev/attestation/coding-workflow/v1",
  "subject": [{"name": "https://github.com/org/repo/pull/42", "digest": {"sha256": "..."}}],
  "predicate": {
    "intent":       { "issue_id": "...", "trigger": "ci-auto-attestation" },
    "execution":    { "branch": "...", "changed_files": [...] },
    "verification": { "tests": [...], "lint": [...], "coverage": {"value": 85} },
    "boundary":     { "compliance": {"ok": true, "reason": "..."} },
    "trace":        { "beads_ids": [...], "commits": [...], "pr_url": "..." }
  }
}
```

Predicate schema: `sdp/schema/coding-workflow-predicate.schema.json`

## FAQ

**Q: Do I need to change how my agent works?**
A: No. SDP observes from CI. The agent writes code normally.

**Q: What if my agent doesn't use beads?**
A: `beads_ids` will be empty. All other fields are populated automatically.

**Q: Can I enforce evidence before merge?**
A: Yes, via branch protection + required check `evidence-gate`. Requires GitHub Pro for private repos.

**Q: Is evidence tamper-proof?**
A: With Sigstore signing enabled, the attestation is uploaded to Rekor (public transparency log) and becomes tamper-evident.
