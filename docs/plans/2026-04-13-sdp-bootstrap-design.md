# SDP Bootstrap: Agent-Ready Setup Generation

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Generate all artifacts needed for AI-native development from analysis data — CLAUDE.md, AGENTS.md, policies, hooks, beads init — so agents can start productive work immediately.

**Architecture:** Consume outputs from scout, architect, metrics, spec, and index to generate agent configuration artifacts. Template-driven with data-backed decisions, not LLM guessing.

**Tech Stack:** Go, text/template, no CGO, no LLM calls.

**Parent design:** `2026-04-13-sdp-toolkit-vision-design.md`

---

## Problem Statement

Setting up a codebase for AI agents takes 30-60 minutes of manual work:
1. Write CLAUDE.md with project conventions (manual, often incomplete)
2. Configure policies for what agents can/cannot do (skipped entirely)
3. Set up git hooks for quality gates (copied from other repos)
4. Initialize issue tracking (forgotten until mid-project)
5. Configure IDE/editor integrations (ad hoc)

Bootstrap automates this with data-backed defaults:

**Before:** Copy CLAUDE.md from another project, manually adjust for 30 min.
**After:** `sdp bootstrap .` → all artifacts generated from actual analysis in 30 seconds.

## Generated Artifacts

### 1. CLAUDE.md (Agent Context Document)

The primary artifact. Generated from real data, not LLM hallucinations.

**Template structure:**

```markdown
# {{.Name}}

{{.Description}}

## Tech Stack
- **Language:** {{.PrimaryLanguage}} ({{.LanguageVersion}})
- **Build:** {{.BuildSystem}} — `{{.BuildCommand}}`
- **Test:** `{{.TestCommand}}`
- **Lint:** `{{.LintCommand}}`

## Architecture
{{.ArchSummary}}

### Key Modules
{{range .Modules}}
- `{{.Path}}` — {{.Purpose}} ({{.LOC}} LOC, owner: {{.Owner}})
{{end}}

## Conventions
- **Commit style:** {{.CommitStyle}}
- **Branch model:** {{.GitFlow}}
- **Test pattern:** {{.TestPattern}}
- **Error handling:** {{.ErrorPattern}}

## Commands
```bash
# Build
{{.BuildCommand}}

# Test
{{.TestCommand}}

# Lint
{{.LintCommand}}

# Run
{{.RunCommand}}
```

## What NOT to Do
{{range .Antipatterns}}
- {{.}}
{{end}}
```

**Data sources for each section:**

| Section | Source | Fallback |
|---------|--------|----------|
| Name, Description | scout.json | README first line |
| Tech Stack | scout.json (build system, language) | Makefile parse |
| Architecture | architect report (style, modules) | Directory structure heuristic |
| Modules | architect report + index (if available) | Top-level dirs with >5 files |
| Commit style | metrics (conventional commits ratio) | git log --oneline analysis |
| Git flow | metrics (detected model) | Branch naming patterns |
| Test pattern | scout (test framework detection) | File pattern `*_test.*` |
| Build/Test/Lint commands | Makefile/package.json/go.mod | Common defaults per language |
| Antipatterns | architect (risks) + metrics (decay) | Generic per-language |

### 3. Policy Files (.sdp/policies/)

OPA/Rego policies for automated guardrails.

**Auto-generated policy: `main.rego`**

```rego
package sdp.policy

# Auto-generated by sdp bootstrap
# Based on: {{.AnalysisSource}}

# Sensitive paths — never auto-edit without approval
sensitive_paths := {
{{range .SensitivePaths}}
    "{{.}}",
{{end}}
}

# Generated files — never edit (will be overwritten)
generated_paths := {
{{range .GeneratedPaths}}
    "{{.}}",
{{end}}
}

# Test requirements per directory
test_required[dir] {
    dir := input.changed_dir
    {{.TestRequiredDirs}}[dir]
}

# Max file size for new files (LOC)
max_new_file_loc := {{.MaxFileLOC}}

# Commit message must match pattern
commit_pattern := "{{.CommitPattern}}"
```

**Sensitive path detection algorithm:**

```
1. Scan for known sensitive patterns:
   - .env*, credentials.*, secrets.*, *.pem, *.key
   - config/production*, deploy/*, infrastructure/*
   - auth/, security/, crypto/

2. Scan for CODEOWNERS-protected paths (if CODEOWNERS exists)

3. Scan for files with >3 contributors (high coordination cost)

4. Scan for architect-flagged high-risk modules
```

### 4. Git Hooks (.sdp/hooks/)

Quality gate hooks, installed via `sdp bootstrap --hooks`.

**pre-commit:**
```bash
#!/bin/bash
# Generated by sdp bootstrap

# Run linter on staged files
{{.LintCommand}} || exit 1

# Check for sensitive files
for f in $(git diff --cached --name-only); do
  case "$f" in
    .env*|*.pem|*.key|credentials.*|secrets.*)
      echo "ERROR: Sensitive file staged: $f"
      exit 1
      ;;
  esac
done
```

**prepare-commit-msg:**
```bash
#!/bin/bash
# Generated by sdp bootstrap
# Validates commit message against detected convention

MSG=$(cat "$1")
{{if .ConventionalCommits}}
if ! echo "$MSG" | grep -qE '^(feat|fix|chore|refactor|docs|test|ci|build|perf|style)(\(.+\))?: .+'; then
  echo "ERROR: Commit message must follow Conventional Commits format"
  echo "Example: feat(api): add user endpoint"
  exit 1
fi
{{end}}
```

**pre-push:**
```bash
#!/bin/bash
# Generated by sdp bootstrap

# Run tests before push
{{.TestCommand}} || {
  echo "ERROR: Tests failed. Push aborted."
  exit 1
}
```

## Bootstrap Algorithm

```
sdp bootstrap <repo-path>
    │
    ├─ 1. Collect analysis data
    │     scout.json   (required — run scout if missing)
    │     architect/   (optional — enriches modules, risks)
    │     metrics/     (optional — enriches conventions, health)
    │     specs/       (optional — enriches API docs)
    │     index.db     (optional — enriches module purposes)
    │
    ├─ 2. Detect existing configuration
    │     Existing CLAUDE.md?  → merge, don't overwrite
    │     Existing .sdp/?      → update, don't reset
    │     Existing hooks?      → warn, offer to extend
    │     Existing beads?      → skip init, offer import
    │
    ├─ 3. Generate artifacts
    │     CLAUDE.md       (from template + analysis data)
    │     AGENTS.md       (if multi-agent setup detected)
    │     main.rego       (from sensitive path scan)
    │     hooks           (from build system + conventions)
    │     beads issues    (from risks + red flags)
    │
    ├─ 4. Verify artifacts
    │     Build command works?     (run and check exit code)
    │     Test command works?      (run and check exit code)
    │     Lint command works?      (run and check exit code)
    │     Hook syntax valid?       (bash -n check)
    │
    └─ 5. Report
          bootstrap-report.json
          Human-readable summary to stdout
```

## Merge Strategy (Existing CLAUDE.md)

If CLAUDE.md already exists, bootstrap must merge intelligently:

```
1. Parse existing CLAUDE.md into sections (by ## headers)
2. For each generated section:
   a. If section exists in current CLAUDE.md:
      - Compare content
      - If different: add generated content as "<!-- sdp-bootstrap: ... -->" comment
      - User reviews and decides
   b. If section is new:
      - Append at appropriate position
3. Never delete user-written content
4. Mark all generated sections with <!-- generated by sdp bootstrap -->
```

For fresh repos (no CLAUDE.md): generate complete file.

## Command Detection

Build/test/lint command detection per language:

| Language | Build | Test | Lint |
|----------|-------|------|------|
| Go | `go build ./...` | `go test ./...` | `golangci-lint run` |
| Go (Makefile) | `make build` | `make test` | `make lint` |
| Node (npm) | `npm run build` | `npm test` | `npm run lint` |
| Node (yarn) | `yarn build` | `yarn test` | `yarn lint` |
| Python (poetry) | `poetry build` | `poetry run pytest` | `poetry run ruff check` |
| Python (pip) | `python setup.py build` | `pytest` | `ruff check` |
| Rust | `cargo build` | `cargo test` | `cargo clippy` |
| Java (Maven) | `mvn package` | `mvn test` | `mvn checkstyle:check` |
| Java (Gradle) | `./gradlew build` | `./gradlew test` | `./gradlew check` |

**Detection algorithm:**
1. Check Makefile for known targets (build, test, lint)
2. Check package.json scripts (build, test, lint)
3. Check CI config for test/lint commands used in pipeline
4. Fall back to language-default commands

**Verification:** Run detected command with timeout (30s) and check exit code. If it fails, mark as "unverified" in CLAUDE.md.

## CLI Interface

```bash
sdp bootstrap <repo-path>              # Full bootstrap
sdp bootstrap --dry-run <repo-path>    # Show what would be generated
sdp bootstrap --force <repo-path>      # Overwrite existing artifacts
sdp bootstrap --only claude-md <repo>  # Generate only CLAUDE.md
sdp bootstrap --only policies <repo>   # Generate only policies
sdp bootstrap --only hooks <repo>      # Generate only hooks
sdp bootstrap --no-verify <repo>       # Skip build/test/lint verification
sdp bootstrap --no-beads <repo>        # Skip beads initialization
sdp bootstrap status <repo>            # Show current bootstrap state
```

## Testing Strategy

1. **Collector tests:** Create temp `.sdp/` with known JSON files, verify data collection.
   - All sources present, partial sources, no sources (fallback mode)

2. **CLAUDE.md tests:** Generate from known data, verify structure and content.
   - Fresh generation (no existing CLAUDE.md)
   - Merge with existing CLAUDE.md (preserve user content)
   - Different languages (Go, Python, Node, Java)

3. **Policy tests:** Generate from known file trees, verify sensitive path detection.
   - Repos with .env files, credentials, CODEOWNERS
   - Repos with no sensitive paths

4. **Hook tests:** Generate hooks, verify bash syntax (`bash -n`).
   - With conventional commits, without
   - Different lint/test commands

5. **Command detection tests:** Create temp repos with known build files.
   - Makefile with targets, package.json with scripts, bare language

6. **Integration test:** Run against sdp_lab repo, verify generated CLAUDE.md is reasonable.

- **Feeds into:** Agent workflow — CLAUDE.md is the primary agent context document

## Design Decisions

1. **No LLM calls.** All content is template-driven from analysis data. LLM adds risk of hallucinated conventions. If users want LLM-polished prose, they edit CLAUDE.md manually.

2. **Graceful degradation.** Bootstrap works with just scout.json (always available). Each additional data source improves quality but isn't required.

3. **Never overwrite user content.** Merge strategy preserves existing CLAUDE.md sections. Generated content is clearly marked. User edits always win.

4. **Verify by running.** Don't guess if `go test ./...` works — run it and report. Unverified commands get a warning in CLAUDE.md.

5. **Templates are files.** Not embedded strings. Users can customize templates in `.sdp/templates/` to match their org's CLAUDE.md format.
